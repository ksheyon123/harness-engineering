# 미추적 설치 — A 에 커밋하지 않고 하네스를 세운다

## 목적

`.claude/` 와 `.githooks/` 를 `.gitignore` 에 넣어 둔 저장소(이하 **A**)에, **A 의 git 히스토리에 하네스 파일을 하나도 남기지 않고** 하네스를 설치할 수 있게 한다. 지금 설치기는 그 무시 규칙을 `git add -f` 로 뚫고 들어가므로 그런 저장소에는 사실상 설치할 수 없다.

## 배경

### A 는 왜 `.claude/` 를 무시하는가

A 의 개발자들이 **각자 다른 하네스를 쓴다.** 하네스를 팀 규약이 아니라 **개인 도구**로 본 판단이고, 그 판단 자체는 옳다. 거기에 하네스 파일을 커밋해 넣는 것은 남의 개인 설정 자리에 팀 파일을 심는 일이 된다.

### 그런데 왜 지금 설치기는 강제로 담는가 — worktree 때문이다

**git worktree 사본은 워킹 디렉터리를 복사하는 것이 아니라 `HEAD` 커밋에서 만들어진다.** 커밋에 없는 파일은 디스크에 있어도 사본에 나타나지 않는다. 하네스는 `developer`·`qa`·작업 세션을 전부 사본 안에서 돌리므로, 하네스 파일이 커밋되지 않으면 **정작 하네스가 필요한 곳에 하네스가 없다.**

`install/tracking.mjs` 의 `IGNORED` 상태와 그 처방(`git add -f -- <경로>`), 그리고 `init apply` 가 그것을 실제로 수행하는 것이 이 사정에서 나왔다. 회피가 아니라 **당시에 알던 유일한 수단**이었다.

### 사본에서 무엇이 살고 무엇이 죽는가 — 이번에 실측했다

임시 저장소에 `.gitignore`(`.claude/`)를 커밋하고, `.claude/settings.json`·`.claude/agents/probe-zebra.md` 를 **커밋하지 않은 채** 중첩 worktree 를 만들어 `claude -p` 로 잰 결과:

| 무엇 | 사본 안에서 | 왜 |
|---|:---:|---|
| `.claude/agents/*.md` | **상속된다** | Claude Code 가 **git main worktree** 를 풀어 그쪽 `.claude/agents/` 를 읽는다. 커밋 안 돼도, 저장소 밖 사본에서도 온다 |
| `.claude/settings.json` 의 훅 | **안 온다** | `settings.json` 은 **cwd(= `CLAUDE_PROJECT_DIR`)의 `.claude/`** 에서만 읽힌다. 사본 안에서 프로젝트 루트는 사본 자신이다 |

음성 대조로 확정했다 — 부모의 미추적 에이전트 파일을 치우면 사본에서도 사라지고, 저장소 **밖**에 만든 worktree 에서도 그 에이전트는 보였다. 파일시스템 조상 순회가 아니라 git 기반 해석이다. 덤으로, 훅이 안 오는 것은 worktree 특유의 현상이 아니라 평범한 하위 디렉터리(`R/sub`)에서도 같았다.

**이 반쪽 상태가 최악이다.** 에이전트는 정상적으로 스폰되는데(층 0 의 `tools:` 화이트리스트까지 그대로 먹어 Bash 가 없다) 종료 훅이 없다:

```
developer 가 끝났다고 선언
  → frontmatter 의 SubagentStop 은 상속돼 등록돼 있다
  → 그 명령이 `node .claude/hooks/verify-green.mjs` (상대경로, cwd = 사본)
  → 사본에 그 파일이 없다 → 모듈 없음 → 훅이 에러로 끝난다(차단이 아니라 통과)
  → 게이트도 안 돌고 인계 커밋도 안 찍힌다
  → developer 는 Bash 가 없어 스스로 커밋 못 하고,
    오케스트레이터는 격리 때문에 남의 사본을 못 건드린다
  → 작업이 사본 안에 갇힌 채 사라진다
```

인계 실패를 알리는 `systemMessage` 도 그 훅 안에서 나오므로, **이 실패는 신호조차 없다.**

작업 세션의 사본도 같은 구멍을 갖는다. `SessionStart` 는 본체에서 이미 돌았으니 역할 주입은 살아남고 `core.hooksPath` 가 절대경로면 층 2 도 살지만, 층 1 훅의 명령이 `${CLAUDE_PROJECT_DIR}/.claude/hooks/path-ownership.mjs` 이고 그 변수는 사본을 가리키므로 **층 1 만 조용히 죽는다.**

### 돌파구 — `post-checkout`

`git worktree add` 는 새 사본 안에서 `post-checkout` 훅을 실행한다. 실측:

| 잰 것 | 결과 |
|---|---|
| 저장소 **밖 절대경로** `core.hooksPath` 의 `post-checkout` 이 `git worktree add` 에서 도나 | **돈다** |
| 그때 cwd 와 `git rev-parse --show-toplevel` | **둘 다 새 사본** |
| 새 사본 생성과 평범한 브랜치 전환을 구별할 수단 | **있다.** 새 사본은 `$1`(old-ref)이 `0000...0` 40자다 |
| 훅 안에서 본체 경로를 얻는 법 | `git worktree list --porcelain` 첫 줄. 사본 안에서도 본체를 가리킨다 |
| 저장소 **밖**에 만든 사본에서도 도나 | **돈다** |
| 훅이 사본 안에 `.claude/`·`.githooks/` 를 실제로 만들 수 있나 | **된다** |
| 심어 넣은 파일이 사본의 `git status` 에 잡히나 | **안 잡힌다.** `.gitignore` 는 추적되므로 사본에도 있고 거기서도 `.claude/` 를 무시한다 |

즉 **커밋 없이 사본에 하네스를 넣을 수단이 존재한다.** 이 spec 은 그 수단을 세우고, 그 위에서 `git add -f` 를 제거한다.

### 실측하다 잡은 함정

`cp -r "$MAIN/.claude/." "$HERE/.claude/"` 는 **조용히 절반만 복사한다.** 목적지(`.claude/worktrees/<사본>/.claude`)가 원본(`.claude`) 안에 중첩돼 있어 복사가 자기 자신을 파고들고, 재귀 방지에 걸린 뒤 나머지 항목이 누락된다. 실측에서 사본에 `worktrees/` 만 남고 `settings.json`·`agents/` 가 안 갔는데 **종료 코드는 0 이었다.**

### 무시 규칙에 얹혀 있는 것도 문제다

지금 설계는 "A 가 마침 `.claude` 를 무시한다" 는 우연에 기대고 있다. 실측 저장소는 `.claude/` 만 무시했는데, 심어 넣은 `.githooks/` 가 본체와 사본 양쪽에서 `?? .githooks/` 로 떴다. `pre-commit` 이 `git add -A`(전체 스테이징)를 강제하므로 **다음 커밋에 그대로 딸려 들어간다.** 하네스는 자기 무시를 자기가 책임져야 한다.

### 배달 수단도 같이 막힌다

`npm i -D` 는 A 의 `package.json` 과 `package-lock.json` 을 고치는데 **둘 다 추적되는 파일**이다. `npm i --no-save` 는 그 둘을 안 건드리지만 A 가 `npm ci` 를 한 번 돌리면 extraneous 로 **말없이 삭제된다.** 전역 설치(`npm i -g`)는 프로젝트당 설치가 아니라 채택하지 않는다(사람 결정). 플러그인은 CLI 단위라 A 하나만 겨냥할 수 없고, 게다가 `isolation: worktree` 와 frontmatter `SubagentStop` 을 가져가지 못한다(실측·문서 양쪽 확인).

남는 길은 **`npx` 로 한 번 실행해 자기 코드를 `.claude/` 안에 푸는 것**이다. 이 패키지는 **런타임 의존성이 0개**라(`vitest` 는 devDependency) 벤더링 대상이 `.mjs` 스물 몇 개와 `.md` 몇 개뿐이다.

## 기능 목록

### 기능: `git worktree add` 가 Claude Code 경로에서도 `post-checkout` 을 부르는지 확인한다

- **의도**: 이 spec 전체가 "Claude Code 가 사본을 만들 때 git 의 worktree 생성 경로를 탄다" 는 전제 위에 서 있다. 순수 git 에서 훅이 도는 것은 실측했지만, **Claude Code 가 그 명령을 쓰는지는 비대화형(`claude -p`)으로 잴 수 없다** — 그 모드에서는 `isolation` 도 frontmatter 훅도 걸리지 않는다. 전제가 틀리면 나머지 기능이 전부 헛돈다. **그래서 가장 먼저 한다.**
- **방식**: 이 저장소(harness-engineering)에 `.githooks/post-checkout` 을 세우되, 첫 단계에서는 **흔적만 남기는 최소 구현**으로 둔다 — 발동 사실·cwd·`$1`·본체 경로를 파일에 append. 그 상태에서 사람이 세션에서 ① `EnterWorktree` 와 ② `developer` 스폰을 각각 한 번씩 수행하고 흔적을 확인한다.
- **주의**:
  - **자동화할 수 없다.** `harness smoke` 에 넣지 마라 — 비대화형에서 판정이 안 나온다. `smoke` 가 이미 하고 있는 것처럼 **사람이 확인할 목록으로 출력**한다.
  - 흔적 파일은 A 의 워킹트리에 남으면 안 된다. `.claude/` 아래에 쓴다.
  - 두 경로(`EnterWorktree` · 서브에이전트 격리)가 **서로 다를 수 있다.** 둘을 따로 기록하고 따로 판정한다.
- **인수기준**:
  - `.githooks/post-checkout` 이 존재하고, `$1` 이 `0000000000000000000000000000000000000000` 일 때만 흔적을 남긴다. 그 외에는 아무것도 하지 않고 종료 코드 0 을 낸다.
  - 흔적 한 줄에 최소 넷이 들어간다: 발동 표식 · cwd · `git rev-parse --show-toplevel` · `git worktree list --porcelain` 첫 줄에서 뽑은 본체 경로.
  - `harness smoke` 의 출력에 **사람이 확인할 항목**으로 두 줄이 찍힌다 — "`EnterWorktree` 로 사본을 만들고 흔적을 확인하라", "`developer` 를 스폰하고 흔적을 확인하라". 자동 판정하지 않고 `?` 로 표기한다.
  - 이 확인 결과를 `docs/measured.md` 에 한 줄로 남긴다(사람이 확인한 뒤). **결과가 음성이면 이후 기능을 진행하지 않고 멈춘다.**

### 기능: `post-checkout` 이 새 사본에 하네스를 심는다

- **의도**: 커밋 없이 사본이 하네스를 갖게 하는 유일한 수단. 이 기능 하나가 이 task 의 심장이다.
- **방식**: 위 최소 구현을 확장한다. 진입점은 셸 껍데기(`.githooks/post-checkout`), 판정과 복사는 옆의 `.mjs` — 기존 `pre-commit`·`pre-push` 와 같은 구조다(git 이 훅을 셸로 부르기 때문).
  1. `$1` 이 40자 0 이 아니면 즉시 종료(브랜치 전환에는 아무것도 하지 않는다)
  2. `git worktree list --porcelain` 첫 줄에서 본체 경로를 얻는다. 그것이 현재 트리와 같으면 종료(본체 자신에서 도는 경우)
  3. **명시 목록**을 본체에서 현재 사본으로 복사한다. 목록의 출처는 `install/managed.mjs` 의 `managedPaths()` 이며, 여기에 `settings.json`·`harness.config.json`·벤더링 디렉터리를 더한다
  4. 복사 실패는 삼키지 않는다
- **주의**:
  - **`.claude/worktrees/` 를 반드시 제외한다.** 목적지가 원본 안에 중첩돼 있어, 통째 복사는 재귀에 걸려 **조용히 절반만 복사하고 성공을 반환한다**(실측). 목록을 명시하는 이유가 이것이다.
  - **복사 목록을 손으로 적지 마라.** `managedPaths()` 에서 짓는다 — 손 목록은 `sync` 가 파일을 하나 더 얹을 때 이 검사만 그것을 모르고, 새 파일은 미추적으로 태어나므로 하필 가장 필요한 순간에 빠진다.
  - 훅이 실패해도 `git worktree add` 자체는 이미 끝난 상태다. **실패를 조용히 넘기면 사본이 반쪽인 채로 에이전트가 시작된다** — 종료 코드와 stderr 로 반드시 드러낸다.
  - 이 저장소처럼 `.claude/` 가 **이미 커밋된** 저장소에서는 사본에 파일이 이미 있다. 그때도 안전해야 한다(덮어써도 내용이 같다).
  - 사본이 저장소 **밖**에 만들어지는 경우에도 동작해야 한다(실측상 훅은 돈다).
- **인수기준**:
  - `.claude/` 가 무시되어 커밋되지 않은 저장소에서 `git worktree add` 를 하면, 새 사본에 `managedPaths()` 의 모든 경로와 `.claude/settings.json` 이 존재한다.
  - 새 사본에 `.claude/worktrees/` 가 **생기지 않는다.**
  - 사본에서 `git status --porcelain` 이 **비어 있다**(심어 넣은 것이 미추적으로 잡히지 않는다).
  - `$1` 이 0 이 아닌 호출(평범한 브랜치 전환)에서는 파일을 하나도 만들지 않는다.
  - 복사 대상 중 하나라도 실패하면 종료 코드가 0 이 아니고, 실패한 경로가 stderr 에 나온다.
  - 본체 자신에서 불렸을 때(본체 경로 == 현재 트리) 아무것도 하지 않는다.
  - `.claude/` 가 이미 커밋된 저장소에서 돌려도 사본의 내용이 본체와 같고 종료 코드가 0 이다.

### 기능: `init` 이 무시 규칙을 뚫지 않는다

- **의도**: (a) 제약의 본체. 설치가 A 의 히스토리에 아무것도 남기지 않게 한다.
- **방식**:
  - `install/tracking.mjs` 의 `IGNORED` 처방에서 `git add -f` 를 **제거**한다. `IGNORED` 는 더 이상 고쳐야 할 상태가 아니라 **정상 상태**다.
  - `init apply` 가 무시되는 경로를 `git add -f` 로 담던 동작을 **삭제**한다.
  - 판정 기준을 "`HEAD` 에 있는가" 에서 **"사본에 도달하는가"** 로 바꾼다. 도달 경로가 둘이 됐다 — **커밋되어 있거나**(기존), **`post-checkout` 이 심어 주거나**(신규).
- **주의**:
  - **`post-checkout` 이 서기 전에 이것부터 하면 안 된다.** 그 순서로 가면 하네스가 사본에서 반쪽인 채로 도는 구간이 생기고, 그 실패는 조용하다. 두 기능은 한 쌍이다.
  - `.claude/` 가 무시되지 **않는** 저장소(이 저장소 같은)에서는 기존 동작이 그대로여야 한다 — 커밋해서 도달하는 것도 여전히 유효한 경로다.
  - `git add -f` 를 지우는 것이지 `tracking.mjs` 의 다섯 상태를 지우는 것이 아니다. 상태는 여전히 진단에 쓰인다.
- **인수기준**:
  - `init apply` 를 무시되는 경로가 있는 저장소에서 돌린 뒤 `git status --porcelain` 과 `git diff --cached --name-only` 가 **둘 다 비어 있다**(스테이징된 것이 없다).
  - `PRESCRIPTION[IGNORED]` 가 `git add -f` 를 지시하지 않는다.
  - `post-checkout` 이 설치돼 있고 경로가 `IGNORED` 이면, 그 경로는 **결함이 아니다** — `init` 의 종료 코드에 영향을 주지 않는다.
  - `post-checkout` 이 **없는데** 경로가 `IGNORED` 이면 결함이고, `init` 이 0 이 아닌 종료 코드를 낸다.

### 기능: 하네스가 자기 무시 규칙을 자기가 책임진다

- **의도**: "A 가 마침 `.claude` 를 무시한다" 는 우연 위에 서 있는 상태를 끝낸다. `pre-commit` 이 `git add -A` 를 강제하므로, 무시되지 않는 하네스 파일은 **다음 커밋에 반드시 딸려 들어간다.**
- **방식**:
  - `init` 이 **`.git/info/exclude`** 에 하네스가 소유한 경로를 적는다. 이 파일은 저장소 로컬이라 커밋되지 않는다 — A 의 `.gitignore` 를 건드리지 않고 목적을 달성하는 유일한 자리다.
  - `harness.config.json` 을 **루트에서 `.claude/` 로 옮긴다.** 루트에 있으면 A 의 무시 목록 밖이라 `git add -A` 에 잡힌다.
  - 기록 항목은 멱등해야 한다 — `init`·`sync` 를 여러 번 돌려도 같은 줄이 쌓이지 않는다.
- **주의**:
  - 이미 있는 `.git/info/exclude` 내용을 지우면 안 된다. **덧붙이기만** 한다. A 가 자기 항목을 거기 둘 수 있다.
  - 경로 이전은 **하위 호환**이 필요하다. 루트에 `harness.config.json` 이 남아 있는 기존 설치가 조용히 기본값으로 돌아가면 안 된다.
  - 이 저장소는 `harness.config.json` 을 두지 않는다(기본값으로 돈다). 그 성질은 유지한다.
- **인수기준**:
  - `init` 후 `.git/info/exclude` 에 하네스 경로가 들어 있고, `init` 을 두 번 돌려도 그 줄이 중복되지 않는다.
  - `init` 전에 `.git/info/exclude` 에 있던 줄이 그대로 남아 있다.
  - 설정 로더가 `.claude/harness.config.json` 을 읽는다.
  - 루트에 `harness.config.json` 만 있는 저장소에서 로더가 그것을 읽고, `doctor` 가 "옮겨야 한다" 를 보고한다.
  - 둘 다 있으면 `.claude/` 쪽이 이긴다.

### 기능: `npx` 로 자기 코드를 `.claude/` 안에 푼다

- **의도**: A 의 `package.json`·`package-lock.json` 을 건드리지 않고 프로젝트당 설치를 성립시킨다.
- **방식**:
  - `init` 이 실행 중인 패키지 자신의 파일 트리를 `.claude/harness/` 에 복사한다. 복사 대상은 `package.json` 의 `files` 가 정하는 것과 같은 집합이어야 한다.
  - `.claude/hooks/*.mjs` shim 이 `.claude/harness/` 를 **상대경로**로 부르게 바꾼다(지금은 패키지 이름으로 bare import 한다 — `node_modules` 상향 해석에 의존한다).
  - 사람이 치는 명령은 git 로컬 alias 로 건다: `git config alias.<이름> '!node "$(git rev-parse --show-toplevel)/.claude/harness/scripts/harness.mjs"'`. `.git/config` 는 커밋되지 않는다.
- **주의**:
  - **A 가 node 프로젝트가 아닐 수 있다.** `node_modules` 가 있다고 가정하지 마라.
  - `.claude/harness/` 도 `post-checkout` 의 복사 목록에 들어가야 한다 — 안 그러면 사본의 shim 이 없는 곳을 가리킨다.
  - 벤더링본 안의 `*.test.mjs` 는 제외한다. 사본에 들어가면 A 의 러너가 주울 수 있다.
  - 이 저장소 자신은 벤더링하지 않는다(`.claude/hooks/` 가 곧 원본이다). 설치 경로와 개발 경로가 갈리므로 shim 해석이 양쪽에서 성립해야 한다.
- **인수기준**:
  - `init` 후 `.claude/harness/` 에 `package.json` 의 `files` 집합이 존재하고 `*.test.mjs` 는 하나도 없다.
  - `init` 전후로 A 의 `package.json` 과 `package-lock.json` 의 내용이 **바이트 단위로 같다**(존재하지 않았다면 여전히 존재하지 않는다).
  - `.claude/hooks/` 의 각 shim 이 `.claude/harness/` 아래 실재하는 파일을 상대경로로 가리킨다.
  - `npm ls` 나 `node_modules` 유무와 무관하게 훅이 동작한다.

### 기능: `harness gate` 가 게이트를 돌리고 마커를 적는다

- **의도**: 지금은 A 의 `package.json` 에 `posttest` 를 배선해 green 인 sha 를 기록하고 `pre-push` 가 그것을 본다. `package.json` 은 추적되는 파일이라 (a) 아래서 못 고친다. 배선이 없으면 **push 가 전부 막힌다.**
- **방식**: `harness.config.json` 의 `gate` 명령을 하네스가 직접 실행하고, **종료 코드가 0 일 때만** verified marker 를 적는다. `posttest` 배선을 `init` 에서 제거한다.
- **주의**:
  - **"성공했을 때만 기록" 보장이 npm 에서 하네스로 넘어온다.** 실패했는데 기록하면 `pre-push` 가 무의미해진다 — 여기가 이 기능의 유일한 급소다.
  - 사본의 테스트가 A 의 러너에 잡히는 문제(실측 172 → 344)를 이 명령이 흡수한다. 그러면 **오케스트레이터가 돌리는 게이트와 사람이 손으로 치는 `npm test` 가 서로 다른 것을 검사하게 된다.** 규약의 "게이트 정의의 단일 출처는 `scripts.test`" 를 이 지점에서 깨는 것이고, **의도된 것이다.** 차이는 "사본의 테스트를 세느냐" 하나로 한정한다.
  - 이 저장소는 `posttest` 를 계속 쓴다. 두 경로가 공존해야 한다.
- **인수기준**:
  - `harness gate` 가 `gate` 명령의 종료 코드를 그대로 전달한다.
  - 종료 코드가 0 일 때만 marker 가 갱신되고, 0 이 아니면 갱신되지 않는다.
  - marker 에 적히는 sha 가 `HEAD` 와 같고, `pre-push` 가 그것을 통과로 읽는다.
  - `init` 이 A 의 `package.json` 에 `posttest` 를 넣지 않는다.

### 기능: `smoke`·`doctor` 가 "사본에 도달하는가" 를 판정한다

- **의도**: 지금 `smoke` 는 "커밋됐는가" 를 묻는다. 미추적 설치에서는 그 질문이 **항상 빨간불**이라 아무 정보도 아니게 된다. 물어야 할 것은 처음부터 **"이 파일이 사본에 도달하는가"** 였다.
- **방식**: 도달 경로 둘을 각각 확인한다 — 커밋되어 있거나, `post-checkout` 이 설치돼 있고 그 복사 목록에 들어 있거나. 후자면 초록이다.
- **주의**:
  - `post-checkout` 의 **존재**만 보지 말고 `core.hooksPath` 가 그것을 가리키는지까지 본다. `smoke` 가 이미 "표기가 아니라 가리키는 곳" 을 보는 방식으로 되어 있다.
  - **조용한 초록을 만들지 마라.** 모르는 것은 `?` 로 낸다.
  - 실제로 사본을 만들어 검사할 수도 있으나, 그건 부작용이 크다. 판정은 배선 검사로 한다.
- **인수기준**:
  - `.claude/` 가 무시되고 `post-checkout` 이 배선된 저장소에서 `smoke` 가 추적 관련 항목에 대해 초록을 내고 종료 코드 0 을 낸다.
  - 같은 저장소에서 `post-checkout` 을 떼면 그 항목이 빨간불이 되고 종료 코드가 0 이 아니다.
  - `post-checkout` 은 있는데 `core.hooksPath` 가 그 디렉터리를 안 가리키면 빨간불이다.
  - `doctor` 가 `harness.config.json` 의 위치와 `core.hooksPath` 가 절대경로인지를 보고한다.

### 기능: `core.hooksPath` 를 절대경로로 세운다

- **의도**: 상대값(`​.githooks`)은 git 이 **각 워킹트리 최상단 기준**으로 풀기 때문에, 사본 안에서는 **사본의 `.githooks`** 를 찾는다. 미추적이면 그것이 없어 층 2 가 통째로 사라진다. 절대경로면 어느 사본에서든 본체의 훅이 불린다(실측).
- **방식**: `init` 이 `core.hooksPath` 를 A 의 절대경로로 설정한다. 이미 다른 값이 점유하고 있으면(husky·lefthook) 덮지 않고 사람에게 넘긴다 — 기존 동작 그대로다.
- **주의**:
  - `post-checkout` 이 사본에 `.githooks/` 를 심어도 **절대경로 설정은 여전히 필요하다.** 심기 자체가 그 훅에 의해 일어나므로, 첫 사본이 만들어지는 시점에는 본체의 훅이 불려야 한다 — 순환을 끊는 것이 절대경로다.
  - Windows 경로 구분자와 공백이 들어간 경로를 견뎌야 한다.
- **인수기준**:
  - `init` 후 `git config core.hooksPath` 가 절대경로이고, 그 경로가 A 의 `.githooks` 를 가리킨다.
  - 사본 안에서 `git commit` 을 시도하면 본체의 `pre-commit` 이 실행된다.
  - 다른 값이 이미 설정돼 있으면 덮지 않고 사람에게 알린다.

## 버린 대안

**전역 설치(`npm i -g`).** A 를 전혀 안 건드리므로 (a) 를 만족하고 CLI 도 공짜로 얻는다. **사람이 기각했다** — 하네스는 프로젝트당 설치여야 한다. 머신 전역에 한 버전만 존재하면 프로젝트마다 다른 버전을 쓸 수 없고, 설치의 단위가 저장소가 아니게 된다.

**플러그인.** CLI 쪽에 설치되어 프로젝트 기준 해석에 안 걸리므로 훅이 사본 안에서 돈다(실측). 그러나 **깔리는 순간 모든 프로젝트의 세션에 붙는다** — 하네스가 없는 저장소까지 오염시킨다. 게다가 플러그인 에이전트는 `isolation: worktree` 도 frontmatter `SubagentStop` 도 못 받으므로(실측 + 문서 확인), `developer`·`qa` 를 못 옮긴다. 절반만 옮겨지면 설치 경로가 둘로 갈린다.

**`~/.claude/` 에 두기.** 사용자 스코프는 정의상 모든 프로젝트에 걸린다. 프로젝트별로 다른 에이전트·훅을 두는 공식 수단이 없다(문서 확인).

**`npm i --no-save`.** `package.json` 을 안 건드리므로 그럴듯하지만, A 가 `npm ci` 를 한 번 돌리면 extraneous 로 정리되어 **말없이 사라진다.** 어느 날 하네스가 없어지는데 원인이 안 보인다.

**훅 명령을 전부 절대경로로 바꾸기(심기 없이).** frontmatter 의 `SubagentStop` 은 사본에 상속되므로, 그 명령을 본체의 절대경로로 바꾸면 **게이트와 인계 커밋은 되살아난다.** 그러나 층 1 과 `SessionStart` 는 못 살린다 — 거기서 없는 것은 명령 경로가 아니라 **`settings.json` 파일 자체**이고, 파일이 없으면 안에 무엇이 적혔든 안 읽힌다. 부분 대증요법이라 채택하지 않는다. 심기는 사본을 본체와 같게 만들어, **이 저장소에서 검증된 동작이 A 에서 그대로** 돌게 한다 — 새로 검증할 조합을 만들지 않는다.

**사본을 저장소 밖에 두기.** 러너가 사본의 테스트를 줍는 문제가 사라진다. 그러나 사본의 `node_modules` 상향 해석이 깨지고(실측: 중첩돼 있어야 성립), 사본 위치를 정하는 것은 Claude Code 라 하네스가 고를 수 있는 것도 아니다.

**spec 을 커밋하지 않기.** (a) 를 문자 그대로 밀면 `harness/` 도 무시 대상이 된다. 그러나 **"spec 커밋 = 사람 승인 = 모드 전환" 축이 통째로 무너진다** — 대체 전환점(파일 존재 등)은 되돌릴 수 없고 승인 시점도 안 남는다. 게다가 spec 은 PR 리뷰어가 인수기준을 읽는 유일한 근거다. **하네스 기계는 안 들어가고, 하네스가 생산한 문서는 들어간다** — 사람이 (가)로 결정했다.

## 범위 밖

- **`.harness/` 이주.** `.claude/` 12개 중 Claude Code 가 자리를 요구하는 것은 일부뿐이라 나머지를 옮길 수 있고 이름 충돌도 사라지지만, 이 task 로 gitignore 문제가 이미 풀리므로 급하지 않다. 경로가 바뀌는 일이라 이것이 끝난 뒤가 안전하다.
- **`spawn` 의 유닉스판**(백로그 H-1). 독립적이다.
- **게이트 플레이크 재현**(백로그 H-1). 독립적이다.
- **충돌 전수 조사.** `plan` 이 아는 충돌만 보는 것을 넓히는 일. 이 task 는 `core.hooksPath` 점유만 기존대로 다룬다.
- **A 의 러너 설정을 고쳐 주는 것.** 러너마다 파일도 형식도 달라 추측 수정은 `core.hooksPath` 를 husky 에게서 빼앗는 것과 같은 종류의 위험이다. `harness gate` 가 명령 쪽에서 흡수한다.
- **`chmod` 를 Windows 에서 검증하는 것.** 실행권한 개념이 없어 POSIX 에서만 의미가 있다. `smoke` 가 이미 `?` 로 찍는다.
- **미추적 설치를 이 저장소 자신에 적용하는 것.** 이 저장소는 `.claude/` 를 커밋한다 — 그것이 임포트와 사본 동작을 A 와 같은 방식으로 먼저 드러내는 장치다. 두 경로가 공존하도록 만들 뿐, 여기를 바꾸지 않는다.
