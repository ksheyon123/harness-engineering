# 2D 들로네 삼각분할 모듈

## 목적

점 집합(2D)을 받아 들로네 삼각분할을 계산하는 순수 ESM 모듈을 `src/delaunay/` 에 만든다. 외부 의존성 없이 `delaunay(points)` 하나를 공개하고, 삼각형·반쪽변·볼록껍질을 인덱스 기반으로 돌려준다.

## 배경

이 저장소는 하네스 자체를 만드는 곳이라 제품 소스(`src/**`)가 하나도 없다. 이 task 는 그 자리에 들어가는 첫 제품 코드이자, 하네스 파이프라인(기획자 → developer → qa → 게이트)이 실제 알고리즘 코드에서 도는지 확인하는 사례가 된다.

알고리즘으로 들로네를 택한 이유는 **인수기준을 성질로 쓸 수 있기 때문**이다. "출력이 들로네 삼각분할이다" 는 `모든 삼각형의 외접원 안에 다른 점이 없다` 로 완전 검증되므로, 해피패스 몇 개만 찍고 green 이 나는 얕은 테스트와 진짜 검증이 구분된다.

Voronoi 다이어그램은 삼각분할 결과에서 파생되므로 나중에 별도 task 로 붙는다. 이번에 `halfedges` 를 함께 내보내는 것은 그 미래 task 가 이 모듈 내부를 다시 열지 않게 하기 위함이다.

## 기능 목록

### 기능: 기하 술어 (`predicates.mjs`)

- **의도**: 삼각분할의 모든 판정이 두 개의 술어 위에 서 있다 — 세 점의 방향(`orient2d`)과 네 번째 점이 외접원 안에 있는가(`incircle`). 이 둘을 한 파일에 격리해야 나중에 정밀도 전략을 바꿀 때 그 파일만 바뀐다.
- **방식**:
  - `orient2d(ax, ay, bx, by, cx, cy)` — 2×2 행렬식 `(bx-ax)*(cy-ay) - (by-ay)*(cx-ax)`. 양수면 CCW, 음수면 CW, 0이면 공선.
  - `incircle(ax, ay, bx, by, cx, cy, dx, dy)` — 표준 3×3 행렬식. **삼각형 `a,b,c` 가 CCW 일 때** 양수면 `d` 가 외접원 **내부**다.
  - `circumcenter(ax, ay, bx, by, cx, cy)` — 외심 `{x, y}`. 세 점이 공선이면 분모가 0 이 되므로 그때는 `null` 을 돌려준다.
  - **배정밀도 부동소수점 그대로 계산한다.** Shewchuk 적응 정밀도 이식도, 외부 의존성 추가도 하지 않는다.
  - 이 파일은 **공개 API 가 아니다** — `src/delaunay/index.mjs` 의 `export` 에 넣지 않는다. 같은 패키지 안이므로 테스트는 직접 import 한다.
- **주의**:
  - `incircle` 의 부호 규약은 **인자 삼각형의 방향에 의존한다.** 호출부가 CW 삼각형을 넘기면 부호가 뒤집힌다 — 호출 전에 CCW 로 정규화하거나, 넘기는 쪽에서 방향을 알고 있어야 한다. 이 규약을 함수 주석에 명시한다.
  - 좌표를 뺄셈으로 먼저 상대화(`ax-dx` 등)하지 않고 큰 절댓값 좌표를 그대로 곱하면 유효숫자가 빨리 날아간다. 표준 형태대로 `d` 를 원점으로 옮긴 뒤 계산한다.
  - `circumcenter` 가 `null` 을 돌려주는 경우를 호출부가 무시하면 `NaN` 이 조용히 전파된다.
- **인수기준**:
  - `orient2d(0,0, 1,0, 0,1)` > 0 이고 `orient2d(0,0, 0,1, 1,0)` < 0 이며 `orient2d(0,0, 1,1, 2,2)` === 0 이다.
  - CCW 삼각형 `(0,0),(1,0),(0,1)` 에 대해 `incircle(..., 0.2, 0.2)` > 0 이고, `incircle(..., 5, 5)` < 0 이며, 외접원 위의 점 `(1,1)` 에 대해서는 `=== 0` 이다.
  - `circumcenter(0,0, 2,0, 0,2)` 는 `{x:1, y:1}` 이다.
  - `circumcenter(0,0, 1,1, 2,2)` 는 `null` 이다.

### 기능: 들로네 삼각분할 (`delaunay(points)`)

- **의도**: 이 모듈의 유일한 공개 함수. 점 집합을 받아 들로네 삼각분할을 돌려준다.
- **방식**:
  - `src/delaunay/index.mjs` 에서 `export function delaunay(points)` 하나만 내보낸다. 클래스가 아니라 함수형이고, 상태를 갖지 않는다.
  - **입력**: `[[x,y], ...]` 를 받고, `[{x,y}, ...]` 도 받아 내부에서 같은 형태로 정규화한다.
  - **출력**: `{ triangles, halfedges, hull }` — 평범한 객체.
    - `triangles`: 정점 인덱스가 3개씩 평평하게 이어진 배열 (`[i0,i1,i2, i3,i4,i5, ...]`). 인덱스는 **원본 `points` 배열 기준**이다.
    - `halfedges`: `triangles` 와 같은 길이. 반쪽변 `e` 의 짝이 되는 반쪽변 인덱스, 짝이 없으면 `-1`. 반쪽변 `e` 는 삼각형 `Math.floor(e/3)` 의 정점 `triangles[e]` 에서 시작한다.
    - `hull`: 볼록껍질을 이루는 정점 인덱스 배열.
  - **알고리즘은 Bowyer–Watson 점진 삽입**이다. 입력 전체를 감싸는 super-triangle 로 시작하고, 점을 하나씩 넣으면서 외접원이 그 점을 품는 삼각형들(캐비티)을 찾아 지우고, 캐비티의 경계 변과 새 점을 이어 다시 채운다. 마지막에 super-triangle 의 세 정점 중 하나라도 쓰는 삼각형을 전부 버린다.
  - super-triangle 은 입력의 바운딩 박스에서 유도해 **모든 입력 점을 확실히 품도록** 충분히 크게 잡는다. 정점 좌표는 원본 점 배열 뒤에 임시로 붙이고, 결과에서는 제거한다.
  - **`triangles` 의 세 인덱스는 전부 CCW 로 정규화한다** — `orient2d` 로 검사해 음수면 뒤의 두 인덱스를 맞바꾼다.
  - **`hull` 은 삼각분할에서 파생한다** — `halfedges` 가 `-1` 인 반쪽변들을 이어 붙인다. 별도의 convex hull 알고리즘을 쓰지 않는다. 순서는 **CCW**, 시작점은 **껍질 위 정점 중 인덱스가 가장 작은 것**으로 고정한다.
  - `halfedges` 는 삼각분할이 끝난 뒤 변(정점 쌍) → 반쪽변 매핑으로 한 번에 만든다. 캐비티를 다시 채우는 도중에 갱신하려 들지 않는다.
- **주의**:
  - **캐비티 경계 추출이 이 알고리즘의 급소다.** 캐비티에 속한 삼각형들의 변 중 **정확히 한 번만 등장하는 변**이 경계다. 두 번 등장하는 변은 캐비티 내부라 버린다. 이 계산이 부동소수점 오차로 깨지면(경계가 닫힌 단순 다각형을 이루지 못하면) 결과는 삼각분할이 아니게 된다 — **조용히 넘어가지 말고 던진다**(아래 인수기준 참조). 내부 불변식 위반은 버그이지 정상 입력이 아니다.
  - super-triangle 을 너무 작게 잡으면 바깥쪽 점들의 삼각분할이 틀리고, 좌표 범위와 무관한 상수(예: `1e9`)로 잡으면 정밀도가 날아간다. 바운딩 박스에서 유도한다.
  - 삼각형을 지우고 다시 채울 때 인덱스 기반 배열을 쓰면 삭제 구멍 관리가 실수의 원천이 된다. 자료구조 선택은 구현자 재량이되, **결과의 `triangles` 에는 구멍(`undefined`·`-1`)이 남으면 안 된다.**
  - `incircle` 은 CCW 삼각형을 전제한다. 알고리즘 도중의 삼각형이 CCW 임을 보장하거나, 넘기기 전에 방향을 맞춘다.
  - 입력이 `[[x,y]]` 인지 `[{x,y}]` 인지를 원소마다 검사하지 말고 첫 원소로 판정하되, 섞여 있으면 그 자체가 잘못된 입력이다.
- **인수기준**:
  - 정사각형 `[[0,0],[1,0],[1,1],[0,1]]` → `triangles.length === 6`(삼각형 2개), `hull` 은 네 점을 전부 포함하고 길이가 4 다.
  - 삼각형 하나 `[[0,0],[1,0],[0,1]]` → `triangles.length === 3`, `hull.length === 3`.
  - 모든 삼각형이 CCW 다: 임의 입력에 대해 결과의 각 삼각형 `(a,b,c)` 에 `orient2d(a,b,c) > 0` 이다.
  - `halfedges.length === triangles.length` 이고, `halfedges[e] !== -1` 인 모든 `e` 에 대해 `halfedges[halfedges[e]] === e` 다(짝 관계가 대칭이다).
  - `halfedges[e] === -1` 인 반쪽변의 개수가 `hull.length` 와 같다(껍질 변의 수 = 짝 없는 반쪽변의 수).
  - `hull` 은 CCW 이고 첫 원소가 껍질 정점 중 최소 인덱스다. 예: `[[0,0],[1,0],[1,1],[0,1]]` → `hull` 은 `[0,1,2,3]` 이다.
  - 캐비티 경계가 단순 다각형을 이루지 못하면 `Error` 를 던진다(메시지에 내부 불변식이 깨졌음이 드러나야 한다).

### 기능: 축퇴 입력 처리

- **의도**: 점 0~2개, 전부 공선, 중복점은 호출부에서 흔한 정상 입력이다. 여기서 던지면 호출부가 매번 방어 코드를 쓰게 된다. 반면 `NaN`/`Infinity` 는 프로그래밍 오류라 조용히 넘기면 안 된다.
- **방식**:
  - **중복점**은 삼각분할 계산에서 제외하되 **원본 인덱스는 유지한다** — 제거된 점은 어느 삼각형에도, `hull` 에도 등장하지 않고, 살아남은 점들의 인덱스는 원본 그대로다. 완전히 같은 좌표(`===`)만 중복으로 본다. 근접 허용오차를 두지 않는다.
  - **점이 3개 미만이거나 (중복 제거 후) 전부 공선**이면 `triangles: []`, `halfedges: []` 를 돌려주고 **던지지 않는다**. `hull` 은 그때도 유효해야 한다:
    - 점 0개 → `hull: []`
    - 점 1개(중복 제거 후) → `hull: [i]`
    - 점 2개 이상이면서 전부 공선 → `hull` 은 **양 끝점 두 개**의 인덱스. 순서는 좌표 사전순(x 우선, 같으면 y)으로 작은 쪽이 먼저.
  - 좌표에 `NaN` 또는 `Infinity` 가 있거나, 점이 `[x,y]`/`{x,y}` 어느 형태도 아니면 **`TypeError`** 를 던진다.
  - **cocircular(한 원 위의 4점) 입력은 결과가 두 가지 중 하나다.** 어느 대각선을 택하든 들로네 성질을 만족하므로 이것은 정상이다. 특정 삼각형 조합을 강제하지 않는다.
- **주의**:
  - 중복 제거 후 인덱스를 다시 매기면(0..k-1) 원본 대응이 깨진다 — **원본 인덱스를 들고 다녀야 한다.** 이게 이 기능에서 가장 틀리기 쉬운 지점이다.
  - "전부 공선" 판정을 부동소수점 `orient2d(...) === 0` 으로만 하면 거의 공선인 입력이 통과해 super-triangle 이 퇴화한다. 판정 자체는 정확히 0 으로 하되, **거의 공선인 입력은 보장 대상이 아니다**(범위 밖 참조).
  - 중복점이 있는 채로 Bowyer–Watson 에 들어가면 캐비티가 비어 경계가 안 나온다 — 제거는 삽입 **전에** 끝나야 한다.
  - 정사각형 4점은 그 자체가 cocircular 다. 인수기준을 특정 대각선으로 쓰면 구현에 따라 깨진다 — 개수와 성질로 쓴다.
- **인수기준**:
  - `delaunay([])` → `{triangles: [], halfedges: [], hull: []}`.
  - `delaunay([[3,4]])` → `triangles: []`, `hull: [0]`.
  - `delaunay([[0,0],[1,1],[2,2]])` → `triangles: []`, `hull: [0,2]`.
  - `delaunay([[0,0],[1,0],[1,0],[0,1]])` → 중복된 인덱스 2 는 `triangles` 에도 `hull` 에도 없고, `triangles.length === 3` 이며 남은 인덱스는 `0,1,3` 이다.
  - `delaunay([[0,0],[NaN,1],[2,2]])` 는 `TypeError` 를 던진다.
  - `delaunay([[0,0],[1,0],[0,1],"nope"])` 는 `TypeError` 를 던진다.
  - 정사각형 4점(cocircular)은 던지지 않고 삼각형 2개를 돌려준다 — 어느 대각선인지는 단언하지 않는다.

### 기능: 들로네 성질 기반 검증 테스트

- **의도**: 값 고정 테스트만으로는 "green 인데 얕다"가 된다. 이 모듈이 진짜 들로네를 계산하는지는 **성질**로만 확인된다 — 어떤 삼각형의 외접원 안에도 다른 점이 없다.
- **방식**:
  - **고정 시드 PRNG 를 테스트 안에 직접 구현한다**(mulberry32, 8줄 남짓). 외부 의존성을 쓰지 않고, 실패했을 때 같은 입력을 재현할 수 있어야 한다.
  - 무작위 점 **N=200** 개를 만들고, 결과의 **모든 삼각형 × 모든 점** 조합을 `incircle` 로 검사한다(O(n·삼각형수), 대략 4만 회 — 빠르다). 삼각형 자신의 세 정점은 제외한다.
  - 같은 무작위 입력에 대해 **위 기능들의 구조적 불변식도 함께 검증한다**: 모든 삼각형 CCW, `halfedges` 짝 대칭, 짝 없는 반쪽변 수 = `hull.length`, 모든 인덱스가 유효 범위.
  - 성질 검증은 **성공한 판정도 값으로 드러나야 한다** — 검사한 삼각형 수와 점 수가 0 이 아님을 단언한다(빈 결과를 통과시키는 검증은 검증이 아니다).
  - 시드는 최소 두 개(예: 1, 42) 이상 돌린다.
- **주의**:
  - 외접원 판정에 부동소수점 여유를 주지 않으면 원 위에 정확히 걸친 점 때문에 실패할 수 있다. **cocircular 는 정상**이므로 판정을 `incircle > 0`(엄밀히 내부)로 하고 `>= 0` 으로 하지 않는다.
  - 무작위 점은 격자 위가 아닌 연속 좌표로 뽑는다 — 격자 좌표는 cocircular·공선이 과하게 자주 나온다.
  - N 을 키우면 O(n²) 검증이 급격히 느려진다. 200 을 넘기지 않는다.
  - 테스트가 실패했을 때 **어느 시드·어느 삼각형·어느 점인지**가 메시지에 나와야 한다. 안 그러면 디버깅이 불가능하다.
- **인수기준**:
  - 시드 1 과 42 각각에 대해 200개의 무작위 점을 삼각분할한 결과에서, 어떤 삼각형의 외접원 내부에도 다른 점이 없다.
  - 같은 검증에서 검사한 삼각형 수가 0 보다 크다.
  - 같은 입력에 대해 `delaunay()` 를 두 번 부르면 완전히 같은 결과가 나온다(결정적이다).

## 버린 대안

- **분할정복 삼각분할** — Bowyer–Watson 보다 최악 복잡도가 좋다(O(n log n) 보장). 그러나 좌우 부분 결과를 잇는 LR-edge 병합 로직이 이 task 전체보다 무겁고, 틀렸을 때 어디가 틀렸는지 격리하기 어렵다. 성능이 요구사항이 되면 그때 이 모듈의 내부만 갈아끼운다 — 공개 API 는 그대로 둘 수 있게 설계했다.
- **sweep-hull (s-hull)** — 실측 성능이 좋기로 알려져 있으나, 시드점 선택과 껍질 뒤집기 순서 같은 트릭에 의존해 **읽어서 정당성을 확인하기 어렵다.** 이 저장소에서는 읽히는 코드가 더 값을 한다.
- **`robust-predicates` 의존성 추가** — 정확하고 짧다. 하지만 이 모듈을 "의존성 없는 순수 ESM" 으로 두기로 한 결정을 깬다. 이 저장소의 `package.json` 은 devDependency 가 vitest 하나뿐이고, 그 상태를 유지하는 것이 하네스 배포판 입장에서도 낫다.
- **Shewchuk 적응 정밀도 술어 직접 이식** — 의존성 없이 정확해진다. 그러나 수백 줄이고, 그 코드 자체는 이 task 의 관심사가 아니다. **더 정확한 것은 사실이나, 이 task 가 확인하려는 것은 들로네 알고리즘과 하네스 파이프라인이지 부동소수점 예외 산술이 아니라서 택하지 않았다.** 대신 `predicates.mjs` 로 격리해 두었으므로 나중에 그 파일만 교체하면 된다.
- **클래스 API (`Delaunay.from(points)`, `.update()`)** — d3-delaunay 관례에 가깝다. 그러나 상태를 갖는 이점은 점을 갱신하며 재삼각분할할 때 나오는데 그것이 범위 밖이다. 지금 클래스로 만들면 아무것도 하지 않는 상태만 생긴다.
- **`hull` 을 별도 convex hull 알고리즘(monotone chain 등)으로 계산** — 더 짧고 독립적으로 검증된다. 그러나 삼각분할 결과와 **어긋날 수 있는 두 번째 출처**가 생긴다. 껍질은 삼각분할에서 파생되는 값이므로 파생시키고, 그 대신 "짝 없는 반쪽변 수 = `hull.length`" 를 인수기준에 넣어 일치를 강제한다.
- **성능 인수기준(예: 10,000점 < 2초)** — 회귀를 잡아 주지만 머신·부하에 따라 깜빡인다. **깜빡이는 게이트는 게이트를 못 믿게 만들고, 못 믿는 게이트는 곧 무시된다.** 성능은 아래 비-인수 메모로만 남긴다.
- **중복점에 근접 허용오차(epsilon) 적용** — 거의 같은 점들을 합쳐 주면 수치적으로 안정해진다. 그러나 허용오차 값이 곧 숨은 정책이 되고, 호출부는 자기 점이 왜 사라졌는지 알 수 없다. **완전히 같은 좌표만** 중복으로 본다.

## 범위 밖

- **Voronoi 다이어그램** — 삼각분할의 쌍대로 파생되지만 이번에 만들지 않는다. `halfedges` 를 내보내는 것으로 다음 task 가 이 모듈 내부를 열지 않아도 되게 해 뒀다.
- **제약 들로네(constrained / CDT)** — 강제 변(edge) 입력을 받는 변형. 알고리즘이 실질적으로 다른 것이 된다.
- **3D(Delaunay tetrahedralization)**, 구면 들로네.
- **시각화·렌더링·CLI** — 이 task 는 모듈 하나다. 그림을 그리는 코드도, 데모 페이지도 만들지 않는다.
- **증분 갱신 API**(`insert(point)` / `remove(point)` / `update()`) — 공개 API 는 `delaunay(points)` 함수 하나다.
- **병적으로 축퇴된 입력에 대한 정확성 보장** — 배정밀도 행렬식을 그대로 쓰므로, 거의 공선이거나 거의 공원인 점들에서는 판정 부호가 뒤집힐 수 있다. **무작위/일반 위치 입력에서는 정확하고, 그 밖에서는 보장하지 않는다.** 보장이 필요해지면 `predicates.mjs` 를 적응 정밀도 구현으로 교체한다.
- **성능 최적화 및 성능 인수기준** — 큰 입력에 대한 튜닝(공간 인덱스, 삽입 순서 정렬 등)을 하지 않는다.
  - *비-인수 메모(테스트로 강제하지 않음)*: 10,000점 정도가 실용적인 시간 안에 끝나는 것이 바람직하다. 인수기준이 아니므로 미달해도 이 task 는 완료된 것으로 본다.
- **TypeScript 타입 선언(`.d.ts`)** — 이 저장소에 타입 빌드 파이프라인이 없다. JSDoc 주석까지가 이번 범위다.
