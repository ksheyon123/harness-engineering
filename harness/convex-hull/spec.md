# convex-hull

## 목적

2D 점 집합의 볼록 껍질(convex hull) 꼭짓점을 QuickHull 로 구하는 순수 함수 `convexHull` 을 만든다. 이 저장소의 **첫 제품 코드**이고, 동시에 역할 기반 파이프라인이 실제 구현 작업에서 도는지 확인하는 시험 작업이다.

## 배경

이 저장소가 만드는 것은 하네스 자체다. 코드가 아주 없지는 않다 — `.claude/hooks/` 에 종료 훅 셋과 그 테스트가 있고 게이트는 green 이다(31 테스트). 하지만 **그것들은 하네스 부품이고, 파이프라인을 통과해 만들어지지 않았다.** 실행자가 저장소 본체에서 직접 고치는 파일들이다(그렇게 하도록 CLAUDE.md 가 명시한다 — 훅을 고치러 `developer` 를 스폰하면 그 훅이 그 developer 의 종료를 검사하는 순환이 생긴다).

즉 `src/` 가 없고, `spec → developer → 게이트 → QA → push` 가 **제품 코드 작업에서 끝까지 도는 것을 아직 아무도 본 적이 없다.**

convex-hull 을 첫 실작업으로 고른 이유는 둘이다:

- **정답이 기계적으로 명확하다.** 인수기준을 검증 가능한 단언으로 쓰기 쉽고, QA 가 "테스트가 spec 을 덮는가"를 판정할 때 주관이 개입할 여지가 적다.
- **얕은 테스트로도 green 이 쉽게 난다.** 정사각형 하나만 통과시켜도 게이트는 초록이다. 퇴화 입력·공선점·중복점이 전부 빠져도 게이트는 그것을 구조적으로 볼 수 없다 — **게이트가 못 보는 것을 QA 가 보는지** 시험하기에 맞는 소재다.

즉 이 task 의 산출물은 convex-hull 코드**와**, 파이프라인이 얕은 커버리지를 잡아내는지에 대한 관찰 둘 다다.

## 기능 목록

### 기능: `convexHull` — QuickHull 코어

- **의도**: 2D 점 집합이 주어지면 그 볼록 껍질의 꼭짓점을 구한다. 라이브러리 없이 순수 함수 하나로 완결한다.
- **방식**:
  - **알고리즘은 QuickHull(분할정복)로 고정한다.** x 가 최소인 점과 최대인 점을 잇는 선분으로 집합을 양쪽으로 가르고, 각 쪽에서 그 선분으로부터 가장 먼 점을 찾아 삼각형을 만든 뒤 바깥쪽 두 변에 대해 재귀한다.
  - 파일은 `src/convex-hull.js`, named export `convexHull`. plain JS ESM(저장소가 `"type": "module"` 이고 tsconfig 가 없다).
  - 테스트는 `src/convex-hull.test.js` (vitest 기본 include 에 잡힌다).
  - 점은 `{ x, y }` 객체. 입력은 그 점들의 배열.
  - **입력을 변형하지 않는다.** 정렬이 필요하면 사본에서 한다. 반환 배열에 입력 객체를 그대로 재사용하는 것은 무방하나, 그 객체의 필드를 쓰지 않는다.
- **주의**:
  - **재귀가 줄어들지 않으면 무한재귀다.** 각 재귀 호출에는 far point 를 제외한 **진부분집합**만 넘긴다. 선분 위(거리 0)나 안쪽 점을 걸러내지 않고 그대로 넘기면 같은 집합이 반복된다.
  - **가장 먼 점이 동률일 때** 어느 쪽을 택하든 최종 껍질은 같아야 한다. 택하는 규칙 자체는 자유지만 결과의 결정론성은 기능 2 의 인수기준으로 강제된다.
  - **선분 위의 점(거리 0)은 버린다.** 공선점 제외(기능 2)가 여기서 갈린다 — 거리 `>= 0` 으로 넘기면 공선점이 껍질에 들어온다.
  - **중복점이 극점일 때** 양쪽 분할에 모두 포함되면 같은 좌표가 두 번 출력된다.
  - 외적/거리 계산은 **정확 비교**로 한다(아래 `## 범위 밖` 참고).
- **인수기준**:
  - 정사각형 꼭짓점 4개 + 내부 점 1개를 넣으면 정사각형 4점만 반환한다.
  - 원 위의 점 n 개(전부 껍질 위)를 넣으면 n 점이 전부 반환된다.
  - 5×5 격자 25점을 넣으면 **모서리 4점만** 반환한다(변 위의 점은 공선이라 제외).
  - 호출 후 입력 배열의 `length` 와 각 원소의 `x`·`y` 가 호출 전과 동일하다(입력 비변형).
  - 반환된 모든 점은 입력에 존재하는 점과 좌표가 일치한다 — 알고리즘이 새 좌표를 만들어내지 않는다.
  - 입력 크기가 커도 무한재귀·스택오버플로로 죽지 않는다: 동일 좌표가 대량 중복된 입력(예: 같은 점 100개 + 정사각형 4점)에서 정상 반환한다.

### 기능: 출력 규약 — CCW · 열림 · 공선점 제외 · 결정론적 시작점

- **의도**: 같은 점 집합이면 **입력 순서와 무관하게 항상 똑같은 배열**이 나오게 한다. 그래야 테스트가 회전 정규화 헬퍼 없이 `toEqual` 로 바로 단언할 수 있다.
- **방식**:
  - **CCW**(반시계) 순서.
  - **열림** — 첫 점을 끝에 반복하지 않는다. 따라서 `length` 가 곧 꼭짓점 수다.
  - **공선점 제외** — 껍질 변 위에 있을 뿐 꼭짓점이 아닌 점은 반환하지 않는다.
  - **시작점 고정** — `x` 가 최소인 점, 동률이면 `y` 가 최소인 점부터 시작한다.
  - 중복 좌표는 반환 배열에 두 번 나오지 않는다.
- **주의**:
  - CCW 판정은 **수학 좌표계**(y 가 위로 증가) 기준이다. 화면 좌표계로 생각하면 부호가 뒤집힌다.
  - 시작점 규칙은 **정규화 단계로 따로 두는 편이 안전하다.** QuickHull 의 자연스러운 출력 순서에 기대면 분할 순서가 바뀔 때 조용히 깨진다.
  - 퇴화 입력(기능 3)에도 이 시작점 규칙이 똑같이 적용된다 — 2점을 반환할 때 어느 점이 먼저인지가 이 규칙으로 정해진다.
- **인수기준**:
  - `[(0,0), (1,0), (2,0), (2,2), (0,2)]` → `[(0,0), (2,0), (2,2), (0,2)]`. `(1,0)` 이 없고 `length === 4`.
  - 반환 배열의 첫 원소는 `x` 최소·(동률 시) `y` 최소인 꼭짓점이다.
  - 반환 배열의 shoelace signed area 가 양수다(CCW).
  - 반환 배열의 마지막 원소가 첫 원소와 같은 좌표가 아니다(열림).
  - 같은 점 집합을 **서로 다른 순서로 섞어** 여러 번(최소 3가지 순열) 호출해도 반환 배열이 전부 `toEqual` 로 동일하다.
  - 정사각형 꼭짓점에 중복 좌표를 섞어 넣어도(예: 각 꼭짓점을 2번씩) 반환은 4점이다.

### 기능: 퇴화 입력 — 살아남은 극점을 반환한다

- **의도**: 껍질이 면을 이루지 못하는 입력에서도 **throw 하지 않고** 의미 있는 극점을 돌려준다. 호출측에 `try/catch` 를 강요하지 않는다.
- **방식**: 점 개수가 3 미만이거나 전부 공선/전부 동일이어도 정상 반환한다. 반환 순서는 기능 2 의 시작점 규칙을 따른다.
- **주의**:
  - **전부 공선일 때 양 끝 두 점만** 남긴다 — 중간 점은 기능 2 의 공선 제외 규칙과 같은 이유로 버린다.
  - **전부 동일점일 때 한 점**이다. 중복 제거가 없으면 n 개가 그대로 나온다.
  - x 최소/최대 극점이 같은 점이 되는 경우(모든 x 가 같은 수직선상 입력)에 QuickHull 의 초기 분할이 성립하지 않는다 — 이 경로를 별도로 처리하지 않으면 대개 여기서 깨진다.
- **인수기준**:
  - `[]` → `[]`
  - `[{x:1,y:1}]` → `[{x:1,y:1}]` (length 1)
  - 서로 다른 두 점 → 그 두 점(length 2), 시작점 규칙 순서로.
  - `[(0,0), (1,1), (2,2)]`(전부 공선) → `[(0,0), (2,2)]` (length 2)
  - `[(3,3), (3,3), (3,3)]`(전부 동일) → `[(3,3)]` (length 1)
  - 모든 x 가 같은 수직 공선 입력(예: `(0,0), (0,1), (0,2)`) → `[(0,0), (0,2)]` (length 2)
  - 위 모든 경우에서 **throw 하지 않는다.**

## 버린 대안

여기 적힌 것은 **이미 기각된 접근이다. 더 짧거나 쉽다는 이유로 되돌아가지 마라.**

| 대안 | 왜 버렸나 |
|---|---|
| **Andrew monotone chain** | 더 짧고 분기도 적다. 그럼에도 QuickHull 을 택한 것은 **분할정복 재귀 구조 자체가 이 시험의 관심사**이기 때문이다 — 무한재귀·동률 far point·퇴화 분할 같은 함정이 있어서, 얕은 테스트로 green 이 나는 상황을 만들기에 적합하다. "이게 더 간단한데요"는 갈아탈 근거가 아니다. |
| **Graham scan** | 기준점 각도 정렬에 부동소수 함정이 monotone chain 보다 많다. |
| **Jarvis march** | O(nh) 라 껍질 점이 많으면 O(n²). |
| **공선점 포함** | 경계 위 모든 점을 돌려주면 렌더링엔 유용하나 중복·동치 판정 규칙이 늘어난다. 최소 표현을 택했다. |
| **CW 순서 / 닫힌 폴리곤** | CCW·열림이 수학 관례이고, 열림이면 `length` 가 곧 꼭짓점 수라 인수기준이 짧아진다. |
| **퇴화 입력에서 throw** | 호출측이 매번 가려내야 한다. 극점 반환이 호출측 부담이 적다. |
| **퇴화 입력에서 빈 배열 반환** | '점이 없었다' 와 '퍼토리였다' 를 구분할 수 없다. |
| **시작점 미규정(회전 동치 허용)** | 구현 자유도는 높지만 테스트가 회전 정규화 헬퍼를 먼저 써야 한다. **그 헬퍼가 틀리면 테스트가 조용히 무의미해진다** — 시험 작업에서 가장 피하고 싶은 실패 모양이다. |
| **TypeScript 도입** | 게이트(`package.json` 의 `scripts.test`)를 건드리는 별개 결정이다. 이 task 에서 같이 하지 않는다. |

## 범위 밖

**아래는 이 task 에서 만들지 않는다. 선의로 넓히지 마라.**

- **입력 검증** — 배열이 아닌 값, `x`/`y` 필드 누락, 숫자가 아닌 좌표, `NaN`·`Infinity`. 던지지도 걸러내지도 않는다. 이런 입력에서의 동작은 **미정의**이고, 그에 대한 테스트도 쓰지 않는다.
- **robust predicate / epsilon 비교** — 외적과 거리는 정확(`=== 0`) 비교로 한다. 부동소수 누적 오차에 대한 강건성은 다루지 않는다.
- **다른 기하 연산** — 3D 껍질, Delaunay 삼각분할, 최소 봉합원, 점-다각형 포함 판정 등.
- **성능 최적화·벤치마크** — 알고리즘이 QuickHull 이면 충분하고, 실행 시간을 측정하거나 단언하지 않는다. (무한재귀로 죽지 않는 것은 기능 1 의 인수기준이지 성능 요구가 아니다.)
- **타입 선언 파일(`.d.ts`) · JSDoc 타입 주석 강제**.
- **패키지 배포 설정** — `package.json` 의 `exports`/`files`/`main` 필드, 버전 범프.
- **시각화·데모·CLI**.
- **`package.json` · `vitest.config.mjs` 수정** — 게이트 정의는 이 task 에서 건드리지 않는다.
- **`harness/index.json` 등록** — 이 파일은 재설계 후 읽는 주체가 없어 존폐가 결정 대기 상태다. 쓰지 않는다.
