# 버블 정렬

## 목적

숫자 배열을 오름차순으로 정렬하는 버블 정렬 함수 `bubbleSort` 를 `src/bubble-sort.js` 에 ESM 으로 추가한다. 입력을 바꾸지 않고 정렬된 **새 배열**을 반환하며, 한 패스에서 교환이 하나도 없으면 즉시 끝낸다.

## 배경

`src/` 가 비어 있는 저장소의 첫 제품 코드다. 하네스(역할 분리 · worktree 격리 · 게이트)가 실제 코드 위에서 도는지 확인하는 자리이기도 해서, 알고리즘 자체는 작고 인수기준은 값으로 못 박을 수 있는 것을 골랐다.

사람이 확정한 결정 넷:

1. **비파괴** — 원본을 건드리지 않고 새 배열을 반환한다. 호출부에서 사고가 안 나고 테스트하기 쉽다.
2. **숫자 배열만** — `compareFn` 인자를 받지 않는다. 범위를 좁혀 인수기준을 값으로 떨어지게 한다.
3. **조기 종료를 넣는다** — 이미 정렬된 입력이 O(n) 이 된다.
4. **배열이 아닌 입력은 `TypeError`** — 인수기준 한 줄로 검증 가능하다.

## 기능 목록

### 기능: `bubbleSort` — 숫자 배열을 오름차순으로 비파괴 정렬한다

- **의도**: 숫자 배열을 오름차순으로 정렬한 결과를 얻되, 호출부가 넘긴 배열은 그대로 남아 있어야 한다.
- **방식**:
  - `src/bubble-sort.js` 에서 **named export** 로 `bubbleSort` 를 내보낸다(`export function bubbleSort(input)`). default export 는 두지 않는다.
  - 입력을 먼저 얕은 복사한 뒤 **복사본 위에서** 인접 원소를 비교·교환한다. 원본은 읽기만 한다.
  - 정렬 알고리즘은 **버블 정렬이어야 한다** — 인접한 두 원소를 비교해 어긋나면 교환하는 패스를 반복한다.
  - 비교는 `>` 로 한다. 같은 값끼리는 교환하지 않는다.
- **주의**:
  - **`Array.prototype.sort` 를 호출해서는 안 된다.** 결과만 맞으면 인수기준은 통과하지만 이 task 의 관심사 자체가 버블 정렬의 구현이다.
  - 빈 배열과 길이 1 배열은 패스가 한 번도 필요 없다 — 루프 경계가 음수 길이로 흘러 예외가 나지 않게 한다.
  - 반환값은 **항상 원본과 다른 배열 객체**다. 빈 배열·길이 1 배열이라고 입력을 그대로 반환하지 않는다.
  - 교환은 반드시 두 원소를 맞바꾼다. 한쪽만 덮어쓰면 값이 복제되고 짧은 입력에서는 그래도 정렬돼 보인다.
- **인수기준**:
  - `bubbleSort([5, 3, 8, 1, 9, 2])` → `[1, 2, 3, 5, 8, 9]`
  - `bubbleSort([])` → `[]`
  - `bubbleSort([42])` → `[42]`
  - `bubbleSort([1, 2, 3])` → `[1, 2, 3]` (이미 정렬된 입력)
  - `bubbleSort([3, 2, 1])` → `[1, 2, 3]` (역순 입력)
  - `bubbleSort([3, 1, 3, 2, 1])` → `[1, 1, 2, 3, 3]` (중복 값이 보존되고, 길이가 5 그대로다)
  - `bubbleSort([0, -5, 10, -1])` → `[-5, -1, 0, 10]` (음수)
  - `bubbleSort([1.5, -0.5, 1.25])` → `[-0.5, 1.25, 1.5]` (소수)
  - **원본 불변**: `const a = [3, 1, 2]; bubbleSort(a);` 후 `a` 는 `[3, 1, 2]` 그대로다.
  - **새 배열**: `const a = [3, 1, 2];` 일 때 `bubbleSort(a) !== a` 가 참이다. `const e = []; bubbleSort(e) !== e` 도 참이다.
  - **조기 종료**: 이미 오름차순인 길이 50,000 배열(예: `Array.from({length: 50000}, (_, i) => i)`)을 정렬하는 호출이 **1초 안에 반환된다.** 조기 종료가 없으면 약 2.5×10⁹ 회 비교가 돌아 이 상한을 넘는다.

### 기능: 배열이 아닌 입력은 `TypeError` 로 거부한다

- **의도**: 잘못된 입력이 조용히 이상한 결과로 흘러가지 않고 호출 지점에서 즉시 드러나게 한다.
- **방식**:
  - 함수 본문 맨 앞에서 `Array.isArray(input)` 로 판정하고, 거짓이면 `TypeError` 를 던진다. 복사·정렬은 그 뒤에 한다.
  - 메시지는 무엇을 기대했는지 알 수 있게 쓴다(예: `bubbleSort: 배열이 필요하다`). **인수기준은 메시지 문구가 아니라 `TypeError` 라는 타입에만 걸린다.**
- **주의**:
  - `typeof x === 'object'` 로 판정하면 `null` 과 일반 객체를 못 가른다. `Array.isArray` 를 쓴다.
  - 문자열은 인덱스 접근과 `length` 가 있어 배열처럼 굴러가 버린다 — 반드시 거부돼야 한다.
  - 인자를 아예 안 주면 `undefined` 이고, 이것도 배열이 아니므로 같은 경로로 거부된다.
- **인수기준**:
  - `bubbleSort('321')` 은 `TypeError` 를 던진다.
  - `bubbleSort(null)` 은 `TypeError` 를 던진다.
  - `bubbleSort(undefined)` 는 `TypeError` 를 던진다.
  - `bubbleSort()` (인자 없음) 은 `TypeError` 를 던진다.
  - `bubbleSort(123)` 은 `TypeError` 를 던진다.
  - `bubbleSort({ 0: 1, length: 1 })` 은 `TypeError` 를 던진다 (유사 배열도 배열이 아니다).

## 버린 대안

- **제자리 정렬(in-place)** — 버블 정렬의 교과서적 형태이고 추가 메모리를 안 쓴다. 그러나 호출부가 넘긴 배열이 조용히 바뀌는 쪽이 사고가 잦고, 원본 불변을 인수기준으로 못 박는 편이 검증이 명확해서 택하지 않았다.
- **비파괴 + 제자리 옵션 둘 다 제공** — 기능이 하나 늘고 옵션 조합마다 인수기준이 붙는다. 이 task 의 크기에 비해 표면적이 커서 버렸다.
- **`compareFn` 선택 인자** — `Array.prototype.sort` 처럼 비교 함수를 받으면 객체 배열·역순까지 커버되지만, 인수기준이 "임의 비교 함수에 대해 옳다"로 넓어져 값으로 못 박기 어려워진다. 숫자 전용으로 좁혔다.
- **조기 종료 없는 순수 n-1 패스** — 더 단순하지만 이미 정렬된 입력이 항상 O(n²) 다. 조기 종료가 있어야 "정렬된 큰 입력이 빠르다"는 관측 가능한 인수기준이 생긴다.
- **패스 수·비교 횟수를 반환값이나 별도 export 로 노출** — 조기 종료를 직접 셀 수 있게 되지만, 그러려고 공개 API 를 넓히는 것은 본말전도다. 대신 **큰 정렬된 입력의 시간 상한**으로 간접 검증한다.

## 범위 밖

- **`compareFn` · 내림차순 · 객체 배열 정렬.** 숫자 오름차순 하나만 한다.
- **제자리 정렬 API.**
- **요소 타입 검증.** 입력이 배열이기만 하면 통과시킨다 — 배열 안에 문자열·객체가 섞여 있을 때의 동작은 정의하지 않는다.
- **`NaN` 이 섞인 배열의 결과 순서.** `NaN` 은 어떤 비교도 거짓이라 위치가 정의되지 않는다. 예외를 던지지도, 특정 위치를 보장하지도 않는다.
- **다른 정렬 알고리즘**(퀵·머지·삽입) 및 알고리즘 간 성능 비교.
- **TypeScript 타입 정의(`.d.ts`) · 패키지 export 엔트리 · README 문서화.**
- **벤치마크 스위트.** 조기 종료 인수기준의 1초 상한이 유일한 성능 관련 검사다.
