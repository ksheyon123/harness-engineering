# drop-phase1

## 목적

QA 에이전트 정의와 설계 문서가 **"이 저장소엔 테스트 러너가 없다"를 전제**하고 있다. `#1` 이 vitest 를 도입해 그 전제는 깨졌는데 서술만 남았다.

이건 문서 오타가 아니라 **동작하는 오지시**다. `.claude/agents/qa.md:53-56` 이 QA 에게 이렇게 지시한다:

> ## Phase 1 주의 (현재 저장소 상태)
> 이 저장소는 아직 테스트 러너가 없어 테스트 코드가 없을 수 있다. 그 경우:
> - 커버리지 열은 모두 `❌ 누락(테스트 없음)`으로 기록한다

QA 는 haiku 로 headless 실행되고 `Bash` 가 없어 테스트를 돌릴 수 없다. 그래서 **커버리지 판단을 전적으로 이 지시문과 정적 읽기에 의존한다.** 지금은 `scripts/gate.test.mjs`(31)·`scripts/worktree-add.test.mjs`(29) 60개 테스트가 실재하는데, 이 절이 QA 를 "전부 ❌" 로 유도할 수 있다. 실패 방향이 나쁘다 — **실제로는 덮여 있는데 누락으로 기록**되면 사람이 PR 에서 잘못된 신호를 보고 판단한다.

## 범위 밖 (명시)

- QA 의 산출물 형식(`qa-checklist.md` frontmatter·매트릭스 열)·도구 경계·비차단 성질. 그대로 둔다.
- `pre-push` 의 QA 호출부. 그대로 둔다.
- `index-sync` 제거(별도 task). **단 같은 파일을 고치므로 머지 순서를 지킨다** — 아래 '주의' 참고.

## 기능 목록

### 기능: `qa.md` 의 Phase 1 절을 조건부 지시로 대체한다

- **의도**: "이 저장소는 테스트가 없다"는 **사실 주장**을 지우고, "테스트 러너가 없는 대상은 그 근거로 기록하라"는 **조건부 규칙**으로 바꾼다. 사실은 시간이 지나면 틀리지만 규칙은 안 틀린다 — `#1` 이 게이트 대상에서 내린 것과 같은 판단이다.
- **방식**: `## Phase 1 주의 (현재 저장소 상태)` 절을 제거하고 다음 취지로 대체한다.
  - 테스트 러너가 있는지는 **`harness/config.json` 의 `gate.test` 항목으로 판단**한다. 해당 대상에 `test` 항목이 없으면 러너가 없는 것이고, 그 사실을 근거로 커버리지를 `❌ 누락(테스트 러너 없음)` 으로 기록한다.
  - 항목이 있으면 **테스트 파일을 실제로 읽어** 커버리지를 대조한다. "테스트가 없을 것"이라고 가정하지 않는다.
  - 기능 체크리스트 독립 도출은 두 경우 모두 정상 수행한다.
- **주의**:
  - QA 는 **`Bash` 가 없어 게이트를 실행할 수 없다.** 그래서 `node scripts/gate.mjs --list` 로 판단하라고 쓰면 안 된다 — `harness/config.json` 을 **Read** 하라고 써야 한다. 이 경계는 CLAUDE.md '검증 명령' 절에 이미 명시돼 있고, 그것과 어긋나지 않게 쓴다.
  - QA 의 도구 목록(`Read, Grep, Glob, Write, Edit`)은 `harness/config.json` 읽기에 충분하다 — 변경 불필요함을 확인한다.
  - `frontmatter` 의 `model: haiku` 도 그대로 둔다.
- **인수기준**:
  - `.claude/agents/qa.md` 에 "Phase 1" 이라는 표현과 "이 저장소는 아직 테스트 러너가 없어" 라는 사실 주장이 없다.
  - 테스트가 있는 대상에 대해 QA 가 "전부 ❌" 로 기록하도록 유도하는 문장이 없다.
  - 러너 유무 판단 근거로 `harness/config.json` 을 Read 하라는 지시가 있다.

### 기능: 설계 문서의 Phasing 서술을 정리한다

- **의도**: `harness-engineering.md` 가 "현재 Phase 1 / 추후 Phase 2" 를 **현재형**으로 서술한다. 이 문서는 다음 도입 프로젝트의 원본이 되므로, 끝난 단계를 현재 상태로 적어두면 그대로 복제된다.
- **방식**:
  - §6 '단계적 도입 (Phasing)' — *"이 저장소엔 현재 테스트 러너가 없다"* 와 Phase 1/2 표를 **설계 이력으로 명시**하거나 제거한다. 남긴다면 "vitest 도입으로 Phase 2 완료" 를 함께 적어 현재 상태를 오해하지 않게 한다.
  - §7.3 pre-push 개념 스케치 — 현재 구현(`gate.mjs` 호출 + 트리 해시 조건부 스킵)과 맞춘다.
  - §10 — *"테스트 러너 — 결정: Phase 1은 `tsc --noEmit`만"* 을 현재 결정(vitest 도입 완료)으로 갱신한다.
  - §11 적용 순서 — 5번의 *"테스트 작성·`npm test`는 Phase 2"* 단서를 제거하고, 현재 프로토콜(test-first)과 맞춘다.
- **주의**:
  - **§11 은 `index-sync-removal` task 도 고친다.** 두 task 가 같은 절에서 겹치므로 **동시에 진행하지 않는다** — `index-sync-removal` 을 먼저 머지하고 이 task 를 그 위에서 진행한다. 이 task 를 시작할 때 최신 `baseBranch` 에서 분기했는지 확인한다.
  - 설계 이력을 지우지 말고 **'설계 변경 이력' 절에 남긴다.** Phasing 은 당시의 정당한 판단이었고, 왜 그렇게 시작했는지가 다음 도입에 정보가 된다.
  - 이 문서는 서술형이라 단일 출처로 모을 수 없다. 정확성 유지는 사람이 PR 에서 책임진다는 것이 이 하네스의 입장이다.
- **인수기준**:
  - `harness-engineering.md` 가 테스트 러너 부재를 **현재 상태로** 서술하지 않는다.
  - §7.3 의 pre-push 서술이 실제 `.githooks/pre-push` 의 동작(게이트 위임 + 트리 해시 스킵)과 어긋나지 않는다.
  - Phasing 이 있었다는 사실과 그 이유가 문서 어딘가에 이력으로 남는다.

## 사람 확인 필요

- **머지 순서 의존이 있다**: `index-sync-removal` → 이 task. 둘 다 `harness-engineering.md` §11 을 고친다.
- 이 task 는 문서·에이전트 정의만 고치므로 **새 테스트가 생기지 않는다.** 객관 게이트는 기존 60개 테스트로 통과하고, QA 매트릭스는 "테스트 대상 없음" 에 가깝게 나올 것이다 — 정상이다. 완성도 판단은 사람이 PR 에서 한다.
