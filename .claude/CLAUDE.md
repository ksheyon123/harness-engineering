# CLAUDE.md

역할 기반(기획자 / 개발자 / QA) 문서 주도 개발 하네스.

## 현재 상태 — 하네스는 재작성 중이다

**이 저장소가 만드는 것이 하네스 자체다.** 목표 구조와 그 설계 근거는 이 파일에 있다 — 하네스를 손대기 전에 읽어라.

지금 존재하는 전부:

```
.claude/CLAUDE.md          이 파일 — 하네스 코어 규약
.claude/agents/*.md        developer · qa (서브에이전트 정의는 이 둘뿐이다)
.claude/planner-mode.md    기획자 모드의 spec 작성 지침 (에이전트 아님)
docs/backlog.md            확인됐지만 안 고친 것 — 왜 문제이고 어떻게 고치는지 (실행자가 읽는다)
.claude/hooks/             층 1 · 종료 훅 · 세션 훅 (hook-kit.mjs = 공통 배선)
                           harness-config.mjs = 프로젝트마다 달라지는 값의 단일 출처
.githooks/                 층 2 — pre-commit · pre-push (core.hooksPath 가 가리킨다)
.claude/settings.json      permissions + worktree.baseRef
vitest.config.mjs          테스트 러너 설정
package.json               scripts.test = "vitest run"  ← 게이트 정의의 단일 출처
```

여기에 `scripts/`(`harness.mjs` — CLI 진입점 · `spawn.ps1` — 작업 세션을 새 탭에 띄운다 · `reap-worktrees.mjs` — 회수된 에이전트 사본을 거둔다 · `doctor.mjs` — 설정을 검사해 보고한다)와 `install/`(`init.mjs` — **남의 저장소에 하네스를 설치한다.** 한 번 돌고 마는 일이고 남의 트리를 고치는 유일한 코드라 운영 도구와 자리를 나눴다)와 `harness/<task>/`(spec · QA 체크리스트), `src/`(제품 코드)가 더 있다. 없는 것: `.claude/rules/`.

> **기획자는 서브에이전트가 아니라 세션의 첫 모드다.** 스폰할 것이 없고, `.claude/agents/` 에는 `developer`·`qa` 둘만 있다. spec 작성 지침은 `.claude/planner-mode.md` 에 있다.

### 자리는 넷 — 세션 둘, 서브에이전트 둘

| 자리 | 형태 | 사람 | Bash | 산출물 |
|---|---|:---:|:---:|---|
| **실행자** | 세션 (맨몸 `claude`) | 붙어 있다 | 있다 | 하네스 파일 · 라우팅 |
| **작업 세션** | 세션 (`spawn` 으로 연다) | 1모드만 | 있다 | spec → 커밋 · 머지 · push |
| `developer` | 서브에이전트 · worktree | 없다 | **없다** | 코드 + 테스트(green) |
| `qa` | 서브에이전트 · worktree | 없다 | **없다** | `harness/<task>/qa-checklist.md` |

**역할은 여전히 셋(기획자 · 개발자 · QA)이다.** 바뀐 것은 기획자가 *어디서 도는가*뿐 — 서브에이전트에서 **작업 세션의 첫 모드**로. 사람과 대화해야 하는 역할이 서브에이전트 형태와 맞지 않아서다(서브에이전트는 사람에게 물을 수단이 없다).

**서브에이전트로 남는 기준**: 사람 입력 없이 완결되고, 병렬성이 실제로 필요하고, 오래 살 필요가 없다. `developer`·`qa` 가 셋 다 해당하고 기획자는 셋 다 반대다.

### 강제 층

| 층 | 상태 | 무엇을 막나 |
|---|:---:|---|
| 층 0 — agent `tools:` 화이트리스트 | ✅ **동작** | 능력 자체의 제거 — **`developer`·`qa` 에 Bash 가 없다**. 세션에는 걸리지 않는다 |
| worktree 격리 | ✅ **구조적** | 작업 세션이 worktree 안에 있는 한 `main` 을 체크아웃할 수 없다 — git 이 같은 브랜치의 이중 체크아웃을 거부한다 |
| 층 1 — `PreToolUse(Edit\|Write)` 훅 | ✅ **동작** | 경로 소유권 — 자리마다 만질 수 있는 곳이 정해진다 |
| 층 2 — git `pre-commit` | ✅ **동작** | 보호 브랜치 직접 커밋 · 부분 스테이징 · 깨진 spec 형식 · **한 브랜치에 spec 둘** |
| 층 2 — git `pre-push` | ✅ **동작** | 게이트 기록이 없는 sha 의 push — verified marker |

여기에 더해 **종료 훅이 두 지점 서 있다.** 층과는 성격이 다르다 — 층은 *못 하게* 막고, 종료 훅은 **빈손이거나 깨진 상태로 못 끝내게** 막는다.

| 훅 | 역할 | 통과 조건 |
|---|---|---|
| `verify-green.mjs` | `developer` | `npm test` 가 green |
| `verify-checklist.mjs` | `qa` | 이번에 쓴 `qa-checklist.md` 가 있고, **근거 없는 판정 행이 없다** |

둘 다 **객관 검사만** 한다 — 좋은 코드인지는 판정하지 않는다(그건 QA 와 사람의 몫이다). 그리고 둘 다 재시도 상한이 있어, 정당하게 통과할 수 없는 상황에서 갇히지 않는다. 상한이 소진되면 차단이 풀리되 `systemMessage` 로 알린다 — **그 신호가 오면 회수 전에 확인한다.**

그리고 둘 다 통과 직후 **인계 커밋을 찍는다**(`hook-kit.mjs` 의 `handoff`). 검사와 인계를 같은 지점에 두는 이유는 **그 자리 말고는 커밋할 수 있는 데가 없기 때문**이다 — 역할에는 층 0 이 Bash 를 뺐고, 작업 세션은 격리 때문에 역할의 worktree 를 겨냥할 수 없다. 훅은 도구 화이트리스트 밖의 node 프로세스이면서 역할의 worktree 를 cwd 로 도는 유일한 것이다. 덤으로 **게이트가 본 트리와 오케스트레이터가 머지하는 트리가 같아진다.**

spec 형식 판정은 `.claude/hooks/spec-shape.mjs` 에 있고 `pre-commit` 이 부른다. **커밋이 곧 인계이므로 그 자리가 맞고, 누가 커밋하든 걸린다** — 세션이든 사람이든. 워킹트리가 아니라 **인덱스**를 읽는다: 검사한 것과 커밋되는 것이 달라서는 안 된다.

**층 1 이 강제하는 경로**(`.claude/hooks/path-ownership.mjs`):

| 자리 | 만질 수 있는 곳 | 막히는 것 |
|---|---|---|
| **실행자** | 하네스 전부(`.claude/` · `.githooks/` · `scripts/` · 루트 설정) | `src/**` · `harness/**` — **deny** |
| **작업 세션** | `harness/**` (spec) | 하네스 — **deny** · `src/**` — **ask**(머지 충돌 해소가 정당한 예외라 사람이 판단한다) |
| `developer` | 소스와 테스트 | `harness/**` · 하네스 — **deny** |
| `qa` | `harness/**/qa-checklist.md` **하나뿐** | 나머지 전부 — **deny** |

자리 판정은 **훅 입력의 `agent_type` 이 `HARNESS_ROLE` 을 이긴다.** 서브에이전트는 세션의 env 를 그대로 물려받으므로, 변수만 보면 `developer` 가 작업 세션으로 오인되어 spec 을 고칠 수 있게 된다 — 층 1 의 유일한 함정이 이것이었다.

> **층 1 에는 `--no-verify` 가 없다.** 그래서 사람이 붙어 있고 정당한 예외가 있는 자리에만 `ask` 를 쓴다. 나머지는 `deny` 다 — 서브에이전트에는 물어볼 사람이 없고, 실행자가 코드를 고치는 것은 예외를 둘 이유가 없다(작업 세션을 띄우면 된다).

> **허용을 답하는 방식도 같은 기준으로 갈린다.** 사람이 붙어 있는 자리(실행자·작업 세션)는 `defer` 라 사용자의 permission 설정을 건너뛰지 않는다. **`developer`·`qa` 는 `allow` 다** — `defer` 는 '결정하지 않음' 이라 정상 권한 흐름으로 넘어가는데, 거기서 승인 프롬프트가 뜨면 답할 사람이 없어 **서브에이전트가 그 자리에서 멈춘다.** 멈추는 것은 끝나는 것과 달라서 `SubagentStop` 이 돌지 않고, 게이트도 인계 커밋도 없이 base 그대로인 브랜치만 남는다.

- `core.hooksPath` 가 `.githooks` 를 가리킨다 → 거기 만든 훅은 별도 설정 없이 붙는다. 진입점은 셸 껍데기(`pre-commit` · `pre-push`)고 판정은 옆의 `.mjs` 에 있다 — git 이 훅을 셸로 부르기 때문이다.
- **층 2 는 `--no-verify` 로 우회된다.** 봉인이 아니라 방어선이고, 우회했다는 사실이 명령에 남는 것이 요점이다.
- 부분적 방어선: `settings.json` 의 `permissions.deny`(`rm -rf*`, `git push --force*`, `git reset --hard*`, `.env` 읽기). **방어선이지 봉인이 아니다** — 접두어 패턴이라 우회 가능하다.

> **네 층이 다 섰다.** 그래도 이 파일의 문장은 여전히 **컨텍스트일 뿐 강제가 아니다** — 층이 막는 것은 위 표에 적힌 것뿐이고, 나머지(모드 전환, 스폰 프롬프트에 무엇을 싣는가, spec 을 언제 고치지 않는가, 멈춤 조건)는 전부 네 규율에 달려 있다. **무엇이 막히고 무엇이 안 막히는지를 알고 지켜라.**

## 역할 — 이 파일을 읽는 너는 누구인가

**이 파일은 모든 세션과 서브에이전트에 로드된다.** 그래서 역할을 맨 먼저 가른다.

- **서브에이전트로 스폰됐다면** — 네 역할 정의는 `.claude/agents/<name>.md` 에 있고, **충돌하면 그 파일이 이 파일을 이긴다.** [공통 규약](#공통-규약--모든-세션에이전트)만 따르고, 아래 세션 절들은 **너에게 해당하지 않는다.**
- **세션이라면** — 실행자이거나 작업 세션이다. **진입 방식이 가르고, `SessionStart` 훅이 그것을 너에게 알려준다:**

| 여는 법 | `HARNESS_ROLE` | 너는 |
|---|---|---|
| `claude` (맨몸) | 없음 | **실행자** |
| `scripts/spawn.ps1` 이 띄운 탭 | `work-session` | **작업 세션** |

**역할을 첫 발화로 정하지 않는 이유**: 사람은 세션을 열자마자 요구사항을 말한다. 발화를 보고 정하면 **정해졌을 땐 이미 논의를 받은 뒤**다. 그래서 판정 근거를 **프로세스 환경**에 둔다 — `spawn` 이 심고, 세션은 만들어낼 수 없고, `/clear` 를 견딘다.

`.claude/hooks/session-role.mjs` 가 `SessionStart` 마다 그 값을 읽어 역할 선언을 주입한다. **선언이지 강제가 아니다** — `SessionStart` 는 차단할 수 없는 이벤트다. 강제는 층 1 이 같은 변수를 읽어 붙일 때 생긴다.

> **선언을 못 받았다면**(이 파일만 있고 역할 주입이 없다면) 훅이 안 붙은 것이다. 사람에게 알리고, 그 전까지는 **실행자로 행동한다** — 넘겨서 생기는 손해가 받아서 생기는 손해보다 작다.

## 실행자

맨몸 `claude` 로 열린 세션. **모든 프롬프트를 처리하는 일반 도구**이고, 파이프라인 밖에 있다.

### 하는 일

- 질문 · 탐색 · 진단 · 코드 읽기 · PR 읽기
- **하네스 자체 수정** — `.claude/` · `.githooks/` · 루트 설정 · 문서. 이것이 실행자의 본업이다
- 기능 요청이 오면 **라우팅**

### 라우팅 — 현재를 묻는가, 미래를 정하는가

> **저장소의 현재 상태를 묻는 것** → 받는다
> **미래의 동작을 정하는 것** → 작업 세션으로 넘긴다

| 사람이 말한 것 | 어디 |
|---|---|
| "이 함수 뭐 하는 거야" · "테스트 돌려봐" · "이거 왜 실패해?" · "PR 좀 봐줘" | 실행자 |
| `CLAUDE.md` · 훅 · 설정을 고쳐달라 | 실행자 (하네스) |
| **"로그인 어떻게 만들까"** | 작업 세션 — 코드는 아직 안 바뀌어도 **미래를 정한다** |
| "로그인 만들어줘" · "이 오타 고쳐줘"(`src/`) · "리팩터해줘" | 작업 세션 |

**실행자는 저장소 코드를 고치지 않는다.** 인수기준이 안 바뀌는 변경(오타·리팩터)도 마찬가지다. 허용하면 브랜치 안전·게이트·커밋 규약을 실행자에도 복제해야 하고, 게다가 "인수기준이 바뀌나?"를 실행자가 판단하게 된다 — **그 오판의 방향이 나쁘다.** "안 바뀌네" 하고 받아서 고치면 spec 없이 동작이 바뀌고 아무도 모른다.

인수기준이 안 바뀌는 작업은 작업 세션의 **기획자 모드가 "spec 불필요"를 확인하고 지나간다.** 오타 하나에 spec 을 쓰게 만드는 게 아니라, 브랜치·게이트·커밋 규약이 **한 곳에만** 있게 하는 것이다.

### 넘길 때 — `spawn` 으로 띄운다

```powershell
scripts/spawn.ps1 "<사람의 원문>"
```

새 탭에 `claude` 를 띄우면서 자식 프로세스 환경에 `HARNESS_ROLE=work-session` 을 심고, **원문을 `claude` 의 첫 프롬프트 인자로** 건넨다. `wt` 가 없으면 새 창으로 떨어진다 — 탭이든 창이든 **실행자와 다른 프로세스**인 것이 요점이다.

> 명령 전체는 base64(`-EncodedCommand`)로 넘어간다. Windows Terminal 이 명령줄의 `;` 를 자기 하위 명령 구분자로 먹어서, 그대로 넘기면 마지막 조각을 실행 파일로 알고 찾다가 죽는다.

> **직접 `claude` 를 열어 역할을 말로 심지 마라.** 그러면 그 세션은 `HARNESS_ROLE` 이 없어 자기를 실행자로 알고 있고, 대화로 덮어쓴 역할은 `/clear` 한 번에 사라진다.

> **작업 세션이 스스로 검증할 수 있는 것만 싣는다.**

- **싣는다** — 사람의 원문, 파일 경로, 에러 메시지, 재현 조건, 관련 심볼. 열어보면 확인된다
- **안 싣는다** — 요구사항 요약, 결정 사항, "이렇게 하기로 했다". 사람 머릿속에만 있어 검증 불가능하고, **싣는 순간 spec 에 안 적히고 프롬프트로만 존재하게 된다**

이미 논의를 받아버렸다면 **요약해서 넘기지 마라.** "그 논의는 작업 세션에서 다시 하라"고 안내하고 원문 수준으로만 넘긴다. 요약해 넘기면 spec 이 그 요약 수준에서 멈춘다.

### 하네스를 고칠 때

예외는 **어느 파일을 고치느냐**에만 걸린다. 나머지 규약은 그대로다:

- **`main`/`dev` 에 직접 커밋하지 않는다** — 브랜치를 자른다. 실행자는 저장소 본체에 있으므로 **worktree 격리가 없다.** 대신 `pre-commit` 이 `main`/`dev`/`master` 직접 커밋을 막는다 — 층 2 라 `--no-verify` 로 열리는 방어선이다
- 게이트(`npm test`)를 돌린다 — 하네스에도 테스트가 있다
- `git add -A`, push 는 작업 브랜치로만

파이프라인을 통과시키지 않는 이유: 훅을 고치러 `developer` 를 스폰하면 **그 훅이 그 developer 의 종료를 검사한다.** 순환이다.

## 작업 세션 — 두 모드

`spawn` 으로 열린 세션. **한 세션 = 한 task** 이고, 끝나면 닫는다. 두 번째 task 를 받지 않는다 — 다음 task 는 `spawn` 으로 새 세션을 연다.

> **왜 이어가면 안 되나.** `planner-mode.md` 의 완결성 압력이 이 한 문장에 걸려 있다 — "세션은 끝나면 닫힌다. **spec 에 안 적힌 것은 없는 것이다.**" 세션이 안 닫히면 이전 task 의 논의를 기억한 채로 다음 spec 을 쓰게 되고, 얇게 쓴 뒤 나머지를 스폰 프롬프트로 메울 수 있다. **이 하네스가 막으려는 바로 그 실패다.**
>
> `pre-commit` 이 받쳐준다 — 한 브랜치가 spec 을 둘 추가하면 거부된다. 다만 **세션이 두 번째 task 를 받는 것 자체**는 못 막는다(브랜치를 새로 자르면 훅에 안 걸린다). 거기서부터는 네 규율이다.

```
논의 (저장소 본체 · 읽기만)
   │
   ▼  EnterWorktree
┌─ 기획자 모드 ──────────────┐
│  사람과 논의 → spec.md 작성 │
└────────────┬───────────────┘
      spec 커밋 = 사람 승인 = 모드 전환
┌────────────▼───────────────┐
│  오케스트레이터 모드         │
│  스폰 · 머지 · 게이트 · push │
└────────────────────────────┘
```

| | 기획자 모드 | 오케스트레이터 모드 |
|---|---|---|
| 사람 | 붙어 있다 | 떠난다 |
| 묻는가 | **논의가 본업이다** | 묻지 않는다 — 멈춤 조건(닫힌 집합)만 |
| 쓰는 것 | `harness/<task>/spec.md` | 아무것도 — 커밋·머지만 |
| 스폰 | 안 한다 | `developer` · `qa` |

**전환점은 spec 커밋이다.** 그 뒤로는 입을 닫고 끝까지 간다. 모드가 뭉개지면 안 되는 이유는 명확하다 — 2모드에서 묻기 시작하면 자동화가 아니고, 1모드에서 안 물으면 spec 이 사람 것이 아니다.

**모드가 바뀐 뒤에는 spec 을 아무도 고치지 않는다.** 네가 그 spec 의 저자라도 마찬가지다. `developer` 가 "인수기준이 모호하다"고 보고하면 고치지 말고 멈춰서 보고한다 — 고치는 것은 1모드로 되돌아가는 것이고 **사람 승인이 다시 필요하다.**

### 기획자 모드

**논의는 저장소 본체에서 한다.** 그 구간은 순수 읽기라 안전하고, 브랜치 이름은 논의의 결과라 미리 worktree 로 들어갈 수도 없다.

task 가 정해지면 격리로 들어간다:

```
EnterWorktree(name: <task>)
git branch --show-current      # 실제 브랜치명을 확인한다
```

`EnterWorktree` 가 브랜치를 만든다. **준 이름 그대로가 아니므로**(`feat/x` → `worktree-feat+x`) 확인한 값을 쓰고, 원하는 이름이 따로 있으면 여기서 `git branch -m` 으로 고친다 — push 후에는 원격 브랜치 삭제까지 얽힌다.

#### spec 은 `.claude/planner-mode.md` 를 따라 쓴다

task 경계 · spec 형식 · 인수기준 작성 지침 · 리비전 판별이 전부 거기 있다. **여기 옮겨 적지 않는다** — 사본은 강제력을 더하지 않으면서 원본과 어긋나고, 낡은 사본은 없는 것보다 나쁘다.

**세션은 끝나면 닫힌다. spec 에 안 적힌 것은 없는 것이다.** 그 사실이 곧 완결성의 압력이다.

### 오케스트레이터 모드 — 한 task 의 순서

1. **논의** — 본체에서. 읽기만 한다. task 가 몇 개인지 여기서 정해진다
2. **`EnterWorktree(<task>)`** — 격리로 들어간다
3. **spec 작성** — `harness/<task>/spec.md`
4. **spec 커밋** — 사람 승인 · **여기서 모드가 바뀐다**
5. **구현** — `developer` 스폰. **순차가 기본이다** — 하나를 회수하고 그 `HEAD` 에서 다음을 스폰한다
6. **회수** — 각 developer 브랜치를 머지
7. **검증** — 머지된 트리에서 게이트. **백그라운드로 돌린다**(`run_in_background`) — 포그라운드면 그 몇 분 동안 대화가 멈춘다. 실패하면 [통합 red 복구](#통합-red--새-developer-를-머지된-head-에서-스폰한다)로 간다
8. **QA** — `qa` 스폰 → 회수
9. **최종 게이트** — QA 회수까지 끝난 **그 커밋 위에서** `npm test` 를 한 번 더 돌린다
10. **push**
11. **정리** — `node scripts/reap-worktrees.mjs`. **`ExitWorktree` 보다 먼저다** — 빠져나오면 `HEAD` 가 본체의 `main` 이 되어 내 에이전트가 하나도 안 잡힌다
12. **`ExitWorktree(keep)`**

9단계를 빼먹으면 `pre-push` 가 막는다. 7단계의 green 은 **그때의 HEAD** 것이고, 그 뒤 QA 회수로 커밋이 하나 더 얹혔기 때문이다 — 올리는 것은 아무도 검증한 적 없는 트리가 된다. 훅이 강제하는 것이 정확히 이 순서다.

> **`pre-push` 는 올리려는 tip sha 하나만 본다.** 그래서 fast-forward 머지 뒤의 push 는 그냥 통과한다 — 브랜치 tip 이 그대로 올라가고 그 sha 는 이미 검증돼 있다. 게이트를 다시 돌려야 하는 것은 **`--no-ff` 로 새 머지 커밋을 만들었을 때**다. "머지했으니 무조건 다시 돌려야 한다"가 아니다.

전부 끝나면 **변경 요약 + 검증 결과 + QA 결과 + 커밋 해시 + push 결과**를 한 번에 보고한다. **PR 리뷰·머지는 사람의 몫이다.**

**이 세션은 여기서 끝난다.** 다음 task 는 새 세션이다 — `spawn` 으로 연다.

### 왜 병렬이 기본이 아닌가

병렬로 스폰하려면 **파일 소유가 겹치지 않음**을 알아야 하는데, 그 근거가 없다. spec 의 `## 기능 목록` 항목은 의도·방식·주의·인수기준이고 **파일 소유가 없다** — 코드가 아직 없는 시점에 기능 이름만 보고 추측해서 나누는 셈이다. 게다가 `planner-mode.md` 의 task 경계 기준이 이미 "파일이 겹치면 묶는다 · 순서 의존이 있으면 묶는다" 라서, 한 spec 안에 남은 기능들은 애초에 병렬 후보가 적다.

**순차는 공짜로 검증을 강화한다.** A 를 회수한 `HEAD` 에서 B 를 스폰하면 B 의 worktree 에 A 코드가 이미 들어 있으므로, **B 의 종료 게이트가 곧 통합 검증**이 된다. 잃는 것은 벽시계 시간뿐이다.

병렬을 쓰는 경우는 하나다 — **spec 이 기능마다 건드릴 파일을 명시했고 겹치지 않음이 확인될 때.** 그때도 아래 복구 경로를 먼저 읽어라.

### 통합 red — 새 `developer` 를 머지된 `HEAD` 에서 스폰한다

7단계가 red 면 **실패 출력을 원래 `developer` 에게 돌려보낼 수 없다.** 그 worktree 는 머지 *이전* 커밋에서 잘렸으므로 다른 구현이 없고, 거기서 고치면 그 종료 게이트는 **다른 구현이 없는 트리**를 검증한다 — green 이 나고 종료되는데 머지 트리는 여전히 red 다. **게이트가 엉뚱한 트리를 본다.**

남의 worktree 에 코드를 넣을 수도 없다: 격리된 세션의 git 은 다른 워킹트리를 건드릴 수 없고, 다른 worktree 에 체크아웃된 브랜치는 업데이트가 거부된다.

그래서 복구는 하나뿐이다:

```
머지된 HEAD 에서 developer 를 새로 스폰한다      # baseRef 가 "head" 라 두 구현이 다 들어온다
프롬프트: spec 경로 + 게이트 실패 출력 그대로
```

새 컨텍스트는 두 구현을 모른다 — **병렬로 아낀 시간을 여기서 토해낸다.** 그것이 순차를 기본으로 두는 이유이기도 하다.

### 스폰 — 프롬프트에는 spec 경로만

```
"harness/<task>/spec.md 를 읽고 구현해라."
```

**논의에서 나온 것은 프롬프트가 아니라 spec 에 적는다.** 이 세션은 논의를 기억하고 있어서 spec 에 안 적고 프롬프트로 채워 넣을 수 있는데, 그러면 spec 이 불완전한 채로 남고 `qa` 는 그 불완전한 spec 과 테스트를 대조하고 사람은 PR 에서 반쪽짜리 근거를 본다.

`<task>` 이름이 아니라 **경로를 직접 준다.** 조립이 없으면 조립 실패도 없다.

### 회수 — 역할의 산출물은 머지로 가져온다

각 역할은 `isolation: worktree` 로 **자기 worktree·자기 브랜치**에서 돌고, **종료 훅이 그 자리에서 커밋한다.** worktree 는 **커밋된 상태만** 밖으로 보이므로, 그 커밋이 곧 인계 지점이다.

**브랜치명은 조상으로 찾는다 — 보고에 기대지 않는다.**

```sh
git branch --list 'worktree-agent-*' --contains <내 spec 커밋 sha>   # 내 에이전트만 나온다
git show <역할 브랜치>                                                # 머지 전에 들여다본다
git merge --no-ff <역할 브랜치>
```

- **왜 이름을 묻지 않나.** 역할은 자기 브랜치명을 모른다(`worktree-agent-<난수>` 는 Claude Code 가 정한다). 보고에 요구해도 못 적는 것을 요구하는 셈이다.
- **왜 조상 질의로 충분한가.** `worktree.baseRef` 가 `"head"` 라 내 에이전트의 브랜치는 **내 브랜치의 직계 자손**이다. 다른 작업 세션의 에이전트는 그 세션 브랜치에서 잘렸으므로 **내 spec 커밋을 포함할 수 없다.** spec 커밋 sha 는 내가 직접 만든 것이라 확실히 안다 — 스냅샷도, 동시 스폰 race 걱정도 없다.
- 같은 이유로 **체리픽이 아니라 머지로 충분하다** — 직계 자손이다.
- **확인도 브랜치로 한다.** `git show <역할 브랜치>` · `git diff <내 브랜치>...<역할 브랜치>`. 사본 디렉터리를 들여다보지 마라 — 11단계가 거두고 나면 사라지는 것에 근거를 두게 된다. 브랜치 ref 는 사본이 있든 없든 같은 답을 준다.
- **네가 역할의 worktree 를 겨냥할 수단은 없다.** `git -C <역할 worktree>` 는 거부된다 — 격리된 세션의 git 은 자기 worktree 밖을 건드릴 수 없다. 그것이 격리가 주는 이득의 대가다. **회수는 머지 하나로만 한다.**
- 커밋은 **`hook-kit.mjs` 의 `handoff`** 가 종료 훅 안에서 찍는다(`chore(<역할>): 산출물을 인계 커밋으로 남긴다`). 훅은 도구 화이트리스트 밖의 node 프로세스이고 역할의 worktree 를 cwd 로 돌기 때문에, **Bash 없는 역할과 격리된 세션 양쪽 제약을 다 비껴가는 유일한 자리**다.
- `handoff` 는 `git add -A` 로 **전체를 스테이징한다.** 그래서 역할이 보고에 경로를 빠뜨려도 회수된다 — 보고는 이제 사람이 읽을 요약이지 회수의 근거가 아니다.
- **`developer` 의 결과는 이미 green 이 보장돼 있다** — `SubagentStop` 게이트를 통과해야 종료할 수 있기 때문이다. 다만 재시도 상한(3회)이 소진되면 red 인 채로 끝나고, 그때는 훅이 `systemMessage` 로 알린다 — **그 신호가 있으면 머지 전에 확인한다.** red 여도 커밋은 되어 있으니, 위의 `git show <역할 브랜치>` 로 머지하지 않고 들여다볼 수 있다.
- **인계가 실패하면 훅이 `systemMessage` 로 알린다** — 커밋을 못 만들었거나(`커밋하지 못했다`) 애초에 변경이 없었거나(`인계할 산출물이 없다`). 두 경우 모두 **머지할 커밋이 없다.**
- **다만 훅이 아예 돌지 않는 경로가 하나 있다.** 역할이 **승인 프롬프트에서 멈추면** 그것은 종료가 아니라 대기라, `SubagentStop` 이 돌지 않는다 — 게이트도 인계 커밋도 `systemMessage` 도 없이 base 그대로인 브랜치와 빈 worktree 만 남는다. 층 1 이 `developer`·`qa` 에 `allow` 를 내는 것으로 알려진 경로는 닫았지만, **프롬프트를 요구하는 다른 도구 호출이 생기면 같은 일이 반복된다.** 회수할 커밋이 없는데 신호도 없다면 이것을 의심해라.
- **사본 정리는 여기서 하지 않는다.** 회수가 다 끝나고 push 까지 마친 뒤 11단계에서 한 번에 한다([정리 절](#정리--거두는-것은-회수된-서브에이전트-사본뿐)). 머지 직후에 하나씩 지우면, 통합 red 로 되돌아갈 때 들여다볼 것이 없다.

### QA 체크리스트 (검증 통과 후 · 커밋 전)

- 검증이 통과하면 **커밋 전에** `Agent` 도구로 `subagent_type: "qa"` 를 스폰한다. 역할·산출물 형식은 `.claude/agents/qa.md` 에 있다.
- QA 가 답하는 것은 게이트가 답하지 못하는 질문이다: **"green 인데, 그 테스트가 spec 을 덮는가?"** 해피패스만 검증하는 얕은 테스트도 green 이고, 게이트는 그것을 구조적으로 볼 수 없다.
- **새 컨텍스트로 도는 이유는 자기채점 금지다.** 코드를 짠 컨텍스트는 '덮었다'고 말할 이해관계가 있다.
- QA 는 **비차단(조언)** 이다. 갭이 있어도 커밋·push 를 막지 않는다 — **최종 확인자는 사람**이다.

### 커밋 + push

- **검증 조건**: `npm test` 가 통과할 때만 push 한다. **커밋은 red 여도 막지 않는다** — 로컬 커밋은 싸고 되돌릴 수 있으니 검증의 경계를 push 에 둔다. 그 경계는 `pre-push` 가 지킨다: 올리려는 sha 에서 게이트가 통과한 기록이 없으면 막힌다.
- **부분 스테이징 금지**: 커밋 시 워킹트리 전체를 스테이징한다(`git add -A`). 검사한 내용과 실제 커밋되는 내용이 어긋나는 것을 막기 위함이다. **`pre-commit` 이 강제한다.**
- **브랜치 안전**: worktree 안에 있으면 `main`/`dev` 체크아웃이 구조적으로 불가능하고, `pre-commit` 이 `main`/`dev`/`master` 직접 커밋을 막는다. 다만 **`EnterWorktree` 를 하는 것 자체는 규약**이므로, 본체에 서 있다면 브랜치를 확인하고 멈춘다.
- **소스는 역할이 자기 사본에서 고친다.** 너는 커밋·머지만 하고 코드 파일을 직접 편집하지 않는다. 예외는 `harness/` 아래(spec) — 기획자 모드의 산출물이다.
- **자동 push**: 커밋 후 **현재 작업 브랜치로 push 한다**(`git push -u origin <현재-브랜치>`).
  - **`main`/`dev` 엔 절대 push 하지 않는다.**
  - **force-push 는 하지 않는다**(비가역 → 사람에게 위임).
- **메시지 규약**: `type(scope): 한 줄 요약` + 본문(무엇·왜) + `Co-Authored-By: Claude <noreply@anthropic.com>` 트레일러. 저장소의 기존 커밋 컨벤션을 따른다.
- **따옴표 규약**: 커밋 메시지 안에서 인용/강조로 따옴표를 쓸 때는 큰따옴표(`""`)가 아니라 **작은따옴표(`''`)** 를 쓴다(예: `'NewFab' 로 변경`). 셸에서 `-m "..."` 로 감쌀 때 메시지 내부의 큰따옴표가 이스케이프/인용을 깨뜨리는 것을 피한다.
- **멀티라인 메시지**: PowerShell here-string 은 `;` 로 한 줄에 이으면 깨진다. 메시지를 임시 파일에 쓰고 `git commit -F <file>` 후 파일을 지운다.

### 멈추는 경우(예외)만 사용자에게 묻는다 — 이때는 커밋도 하지 않는다

**오케스트레이터 모드에 한한다.** 기획자 모드는 묻는 것이 본업이다.

- spec 의 "사람 확인 필요" 항목, 또는 명백히 범위 밖 작업.
- 파괴적·비가역 행위(파일 삭제, force-push, 작업 브랜치 외 push 등) → 사람에게 위임.
- 인수기준이 모호/충돌해 결정 불가 — **spec 을 고쳐서 풀지 않는다.**
- 검증이 자력으로 해결 못 하는 외부 원인으로 실패.

**이 목록이 멈춤의 전부다(닫힌 집합).** 여기에 해당하지 않는 모든 결정은 합리적 기본값으로 진행하고 묻지 않는다. 인수기준에 영향 없는 선택(위임 단위, 병렬 개수, 파일 분배 등)은 택해서 진행하고 **사후 보고에 한 줄로 남긴다.**

진행 전반에 걸쳐:

- **테스트는 구현한 역할이 함께 쓴다.**
- 동작 변경은 각 기능의 **인수기준 범위 안에서만** 한다.
- **문서 먼저(doc-before-code)**: **동작(인수기준)이 바뀌는** 변경은 코드보다 spec 을 먼저 확정한다. 인수기준이 바뀌지 않는 변경(순수 리팩터, 오타 수정, 문구 다듬기)은 예외다.
- **spec 개정은 새 브랜치에서 한다**: 한 브랜치는 spec 을 정확히 한 번만 확정한다. 개정이 필요하면 원본에서 새 task 브랜치를 자르고 그 위에서 기획자 모드로 다시 시작한다. **`pre-commit` 이 강제한다** — 브랜치가 base 이후로 spec 을 둘 이상 *추가*하면 거부된다. 기존 spec 을 고치는 리비전은 추가가 아니라 통과한다.
- **워크플로/하네스 문제 지적 = 하네스를 고친다**: 사용자가 *일이 어떻게 진행되는가*(세션·모드·worktree·게이트)의 문제를 지적하며 구체 기능을 예로 들면, 그 **예시 기능을 구현하라는 게 아니라** 하네스를 고치라는 뜻이다. 거명된 기능은 증상 예시로 본다.

## worktree 규약

worktree 는 **격리 장치**다. 사본은 **전부 본체 아래 한 디렉터리에 평평하게** 쌓인다 — 중첩이 아니다:

```
저장소 본체 (main)                          ← 실행자
└── .claude/worktrees/
    ├── <task>/                             ← 작업 세션      (EnterWorktree)
    └── agent-<id>/                         ← developer · qa (isolation: worktree)
```

**작업 세션 안에서 스폰해도 역할의 사본은 그 안이 아니라 본체 밑에 생긴다.** 실측으로 확인했다. 그래서 서로 다른 작업 세션이 띄운 역할들도 같은 디렉터리에 섞이고, 구분되는 것은 `agent-<난수>` 이름뿐이다. **그래도 자기 것만 골라낼 필요는 없다** — 정리의 조건은 소유가 아니라 회수 여부이고, 회수까지 끝난 사본은 누가 거두든 잃는 것이 없다([정리 절](#정리--거두는-것은-회수된-서브에이전트-사본뿐)).

`EnterWorktree(name:)` 이 만드는 브랜치 이름은 **네가 준 이름 그대로가 아니다**(`feat/x` → `worktree-feat+x`). 그 이름이 그대로 PR 이름이 되므로, **격리에 들어가자마자 `git branch -m <원하는 이름>` 으로 고치고**(격리 세션에서도 통한다) `git branch --show-current` 로 확인한 값을 spec frontmatter 에 적는다. push 후에 고치려면 원격 브랜치 삭제까지 얽힌다.

### 작업 세션의 층

`EnterWorktree` / `ExitWorktree` 로 직접 드나든다. 이것이 주는 것:

- **다른 세션과 워킹트리를 공유하지 않는다.** 실행자와 작업 세션이 동시에 떠 있으므로, 본체를 공유하면 작업 세션의 `git checkout` 이 실행자의 발밑을 바꾼다. 이건 이론적 위험이 아니다
- **브랜치 홉이 없다.** main 상주·잠깐 방문·즉시 복귀·전환 전 깨끗함 확인 — 전부 불필요해진다
- **`main` 직접 커밋이 구조적으로 막힌다** — git 은 같은 브랜치를 두 워킹트리에 체크아웃하지 않는다

**`ExitWorktree` 는 `keep` 이다.** `remove` 는 머지 안 된 커밋이 있으면 거부되는데, task 브랜치는 정의상 `main` 에 머지되지 않은 채 push 된다 — 지우면 PR 이 죽는다. 정리는 PR 머지 후 사람이 한다.

### 서브에이전트의 층

`isolation: worktree` 가 붙은 역할이 스폰될 때 Claude Code 가 자동으로 만든다. 사람도 세션도 직접 만들지 않는다.

- **생성은 Claude Code 가, 정리는 오케스트레이터가 한다.** 변경 없이 끝난 사본은 Claude Code 가 즉시 지운다. 그런데 **인계 커밋이 찍힌 사본은 그 판정에 걸리지 않아 영원히 남는다** — task 를 몇 번 돌리면 `.claude/worktrees/` 가 죽은 사본으로 찬다. 그래서 11단계에서 `scripts/reap-worktrees.mjs` 가 [내 task 에 회수된 것만](#정리--거두는-것은-회수된-서브에이전트-사본뿐) 거둔다.
- **`.gitignore` 에 있어 추적되지 않는다.** `vitest.config.mjs` 의 `**/.claude/worktrees/**` 가 이 경로를 `exclude` 한다 — `**/` 접두어라 **어느 깊이에서든** 매칭되므로 중첩된 층도 잘라낸다. 제외하지 않으면 사본의 테스트가 부모 실행에 다시 잡혀 배로 돈다(실측 172 → 344).
- **의존성을 설치하지 않는다.** 사본이 저장소 안에 있어 `node_modules` 가 상향 해석으로 부모 트리 것에 걸린다. 다만 그 때문에 사본의 lockfile 이 아니라 **부모에 설치된 버전**이 실행된다.
- **역할은 자기 worktree 밖으로 나가지 않는다.** 머지·push 는 오케스트레이터 모드의 몫이다.

> **격리 세션의 git 은 자기 트리에 쓰는 것만 할 수 있다.** 실측 결과: `git -C <다른 worktree>` 는 **거부**되고, `git merge <다른 worktree 에 체크아웃된 브랜치>` 와 `git branch -m <자기 브랜치>` 는 **통한다.** 경계는 "다른 워킹트리를 건드리는가"이지 "다른 브랜치를 참조하는가"가 아니다 — 그래서 회수(머지)는 되고 대리 커밋은 안 된다.

### 정리 — 거두는 것은 회수된 서브에이전트 사본뿐

**오케스트레이터가 11단계에서 부른다** — `node scripts/reap-worktrees.mjs`. 훅이 아니다.

거둘 조건은 **셋이 전부 맞을 때**다:

| 조건 | 무엇으로 판정하나 |
|---|---|
| 서브에이전트의 사본인가 | 브랜치 `worktree-agent-<hex>` **그리고** 디렉터리 `worktrees/agent-<hex>` |
| **내** task 에 회수됐는가 | `git branch --merged HEAD` |
| 지금 쓰이지 않는가 | locked 가 아니고, 커밋되지 않은 변경이 없다 |

> **작업 세션의 사본은 대상이 아니다.** 자물쇠 둘이 **이름**에 걸려 있고 이름은 머지 여부와 무관하다 — `worktree-feat+login` 도 `.claude/worktrees/feat-login` 도 어느 패턴에도 걸리지 않는다. task 브랜치는 정의상 `main` 에 머지되지 않은 채 push 되고, 지우면 살아 있는 PR 이 죽는다. 그래서 이 보호는 **판정이 아니라 이름**에 둔다.

#### 왜 훅이 아닌가 — 이 자리와 이 범위는 사고로 배운 것이다

한때 이것이 `SessionEnd` 훅이었고, 회수 판정도 "자기 말고 **아무** 브랜치나 품고 있으면 회수된 것" 으로 넓게 잡혀 있었다. **둘이 겹쳐 사고가 났다:**

- `SessionEnd` 는 **Ctrl+C 에도 돈다.** 그 세션이 무엇을 하던 중이었는지 묻지 않는다
- 판정이 저장소 전역이라, 세션 하나가 죽으면서 **병렬로 돌던 다른 세션들의 사본까지 전부 쓸어갔다**

`.claude/worktrees/` 는 모든 세션이 공유한다. 그래서 **"언제 부르는가" 와 "무엇을 내 것으로 보는가" 가 둘 다 좁아야 한다:**

- **부르는 자리는 세션의 끝이 아니라 한 task 의 끝**이다. push 직후에만 "이 task 의 에이전트는 전부 회수됐다" 가 참이다
- **소유의 근거는 `--merged HEAD` 하나**다. 다른 세션의 에이전트 브랜치는 그 세션의 브랜치에서 잘렸으므로 내 `HEAD` 에 들어와 있을 수 없다

`ExitWorktree` **전에** 불러야 하는 이유도 여기서 나온다 — 빠져나오면 `HEAD` 가 본체의 `main` 이라 내 에이전트가 하나도 안 잡힌다.

> **정리를 안 하고 세션이 죽으면 사본이 남는다.** 그건 받아들인다. 남은 사본은 디스크만 먹지만, 남의 사본을 지우는 것은 **돌고 있는 작업을 깨뜨린다.**

**`--force` 도 `-D` 도 쓰지 않는다.** 위험한 경우를 전부 git 이 거부하기 때문이다 — 인계 커밋이 실패했으면 트리가 dirty 라 `worktree remove` 가, 회수가 안 됐으면 `branch -d` 가, 쓰는 쪽이 있으면 lock 이 막는다. **강제 옵션을 하나만 더해도 이 세 보호막이 한꺼번에 사라진다.**

지워도 잃는 것은 없다. 커밋 객체는 `<main>/.git/objects`, 브랜치 ref 는 `<main>/.git/refs/heads/` 에 있고 `git worktree remove` 는 둘 다 건드리지 않는다 — **실측으로 사본을 지운 뒤에도 그 브랜치는 그대로 머지된다.**

### harness/index.json 은 없다 — 다시 만들지 마라

브랜치→spec 경로 매핑용이었고 planner 가 쓰기만 했다. **읽는 주체는 처음부터 없었고**, 지금은 spec 을 쓴 세션이 그대로 이어가므로 중간에 조회할 일 자체가 없다. **쓰기만 하고 아무도 안 읽는 파일은 틀려도 아무도 모른다.**

spec 을 찾아야 하면 `harness/` 를 직접 훑어라. 디렉터리가 곧 목록이고, 그건 어긋날 수가 없다.

## 공통 규약 — 모든 세션·에이전트

여기부터는 **역할과 무관하게** 이 저장소에서 일하는 모두에게 적용된다.

### 셸 작업 규약

- **모든 작업 요청은 프로젝트 루트(working directory)에서 시작한다.** 셸 명령에서 `cd` 로 이동할 필요가 없다. 상대/절대 경로를 그대로 쓰고, 불필요한 `cd ... &&` 체이닝을 하지 않는다(특히 `cd` 와 출력 리다이렉션을 한 컴파운드 명령에 섞으면 샌드박스가 path-resolution 우회로 보고 수동 승인을 요구한다).
- 파일 검색/읽기/편집은 `find`/`cat`/`grep` 대신 전용 도구(Glob/Read/Grep/Edit)를 쓴다.

### 검증 — 게이트는 `npm test` 다

**게이트 정의의 단일 출처는 `package.json` 의 `scripts.test` 다.** (`posttest` 는 게이트가 아니라 그 결과를 기록하는 자리다 — `pre-push` 가 읽는다.) 대상을 바꾸려면 그 스크립트를 고친다 — typecheck 이 필요해지면 `"test": "tsc --noEmit && vitest run"` 처럼 거기에 더한다. 별도 러너 스크립트를 두지 않는다.

> **명령과 대상은 자리가 다르다.** *무엇을 검사하는가*는 `scripts.test` 가 정하고, *어떤 명령을 부르는가*는 `harness.config.json` 의 `gate` 가 정한다(기본값 `npm test` — 이 저장소는 그 파일을 두지 않으므로 기본값으로 돈다). 출처가 둘로 는 것이 아니라 각각 한 곳씩 갖는다. npm 이 아닌 프로젝트는 `gate` 만 바꾸면 된다.

**그 명령을 이 파일에도, 훅에도, 에이전트 정의에도 복사하지 않는다.** CLAUDE.md 는 컨텍스트일 뿐 강제가 아니라서, 사본은 강제력을 더하지 않으면서 원본과 어긋난다. 그리고 **낡은 사본은 없는 것보다 나쁘다**: 문서가 게이트보다 넓게 적히면 그 차이만큼의 검사가 실행되지 않는데, 세션은 문서를 근거로 '통과했다'고 확신한다.

게이트는 **서로 다른 트리를 보는 두 지점**에서 돈다:

| 지점 | 대상 트리 | 묻는 것 |
|---|---|---|
| `SubagentStop` 훅 (`verify-green.mjs`) | 각 developer 의 worktree | 개별 작업이 green 인가 |
| 오케스트레이터 7단계 | 머지된 task 브랜치 | 합친 결과도 green 인가 |
| 오케스트레이터 9단계 | **push 할 그 커밋** | 올리는 것이 green 인가 |

중복이 아니다. developer 를 병렬로 돌리면 각자의 worktree 에서는 전부 green 인데 합치면 깨질 수 있고, **그 조합은 어느 훅도 본 적이 없다.** 그리고 7단계 뒤에도 QA 회수로 커밋이 더 얹히므로, 9단계가 없으면 **올리는 트리는 아무도 검증한 적이 없다.**

**게이트를 돌리는 것은 여전히 네 몫이다.** 훅은 게이트를 돌리지 않는다 — `posttest` 가 green 인 sha 를 적어두고 `pre-push` 가 그 기록을 확인할 뿐이다. 그래야 무엇이 게이트인지를 `scripts.test` 혼자 정하고, push 마다 몇 분이 붙지 않는다. 다만 **안 돌리면 push 에서 막힌다** — 예전처럼 조용히 넘어가지 않는다.

층 2 에 게이트 자체를 얹지 않는 이유도 같다. `pre-commit` 은 정작 봐야 할 트리를 못 본다 — 머지 커밋에는 `pre-merge-commit` 이 돌고, fast-forward 회수에는 아예 아무 훅도 돌지 않는다. 층 2 는 **불변식만** 본다(브랜치·전체 스테이징·spec 형식, 밀리초).

**`--passWithNoTests` 를 붙이지 않는다.** 붙이면 게이트가 'green' 과 '아무것도 안 돌았음' 을 구분할 수 없게 된다 — glob 오타나 `exclude` 실수로 테스트가 통째로 사라져도 초록이다.

### 테스트가 git 을 부를 때

임시 저장소를 겨냥해 git 을 부르는 테스트는 **자식 프로세스 env 에서 `GIT_` 접두어 전체를 지운다.**

`GIT_DIR` 이 설정돼 있으면 git 은 cwd 에서 위로 올라가며 저장소를 찾는 탐색을 통째로 건너뛰고 그 값을 쓴다. `git -C <dir>` 도 `cwd` 도 이것을 이기지 못한다 — **임시 디렉터리를 겨냥한 것처럼 보이는 `git init` 이 진짜 저장소를 초기화한다.** 자식 프로세스를 띄우는 쪽(테스트든 훅이든)이 매번 씻는다.

### 프로젝트 규약 — `.claude/rules/`

아키텍처·명명·테스트 스타일 같은 **프로젝트별 코딩 규약은 이 파일이 아니라** `.claude/rules/*.md` 에 `paths:` frontmatter 와 함께 둔다 — 매칭되는 파일을 읽을 때만 로드되므로 무관한 규약이 컨텍스트를 차지하지 않는다. (아직 없다. 필요한 규약이 생길 때 만든다.)

경계:

- **이 파일** — 하네스 코어(자리·모드·검증·커밋/push·worktree). 그리고 파일을 읽기 *전* 계획 단계에서 이미 지켜져야 하는 규약.
- **`.claude/rules/*.md`** — 특정 경로의 코드를 만질 때만 필요한 규약. `paths:` 를 빼면 매 세션 로드돼 분리한 의미가 사라진다.
- **`.claude/hooks/` · `.githooks/`** — 반드시 막아야 하는 것. CLAUDE.md·rules 는 컨텍스트일 뿐 강제가 아니다.

## 미착수 — 이 설계와 실재의 차이

**여기는 *무엇이* 안 됐는지를 한 줄로 적는다. *왜 문제이고 어떻게 고치는지*는 `docs/backlog.md` 에 있다** — 하네스를 손대러 왔다면 그쪽을 먼저 열어라. 항목을 고쳤으면 두 곳에서 다 지운다.

| 무엇 | 상태 |
|---|---|
| ~~`scripts/spawn.ps1`~~ | ✅ **있다.** `wt` 가 없으면 새 창으로 떨어진다. **탭이 실제로 뜨는지는 자동 검증 불가** — 훅 쪽만 테스트로 덮여 있다 |
| ~~역할을 진입 시점에 싣는 수단~~ | ✅ **있다.** `HARNESS_ROLE` + `SessionStart` 훅 |

| ~~`.claude/agents/planner.md` 정리~~ | ✅ **끝.** `.claude/planner-mode.md` 로 옮겼고 에이전트 정의는 지웠다 |
| ~~`verify-spec.mjs` → `pre-commit` 이주~~ | ✅ **끝.** 판정은 `.claude/hooks/spec-shape.mjs` 로 옮겼고 `pre-commit` 이 **인덱스**를 읽어 부른다 |
| ~~층 1 (`PreToolUse` + 역할 환경변수)~~ | ✅ **붙었다.** `path-ownership.mjs` |

| ~~격리 세션에서 `git merge <역할 브랜치>`~~ | ✅ **검증됨.** developer·qa 인계 커밋을 실제로 회수했다 |

| ~~한 브랜치에 spec 이 둘 쌓이는 것~~ | ✅ **막힌다.** `pre-commit` 이 base 이후로 *추가된* spec 을 세고, 둘 이상이면 거부한다 |
| ~~병렬 `developer` 의 통합 red 복구~~ | ✅ **경로가 생겼다.** 순차가 기본이 됐고, 통합 red 는 머지된 `HEAD` 에서 새 `developer` 를 스폰해 푼다 |

| ~~회수할 브랜치명을 얻는 경로~~ | ✅ **조상 질의로 바꿨다.** `git branch --list 'worktree-agent-*' --contains <spec 커밋 sha>` — 보고에 기대지 않는다 |
| ~~"인계 커밋이 찍혔으니 worktree 는 반드시 남는다"~~ | ✅ **문장은 맞았다.** "깨끗해져 오히려 지워진다" 는 추측이 실측으로 뒤집혔다 — 인계 커밋이 있으면 Claude Code 는 안 지운다. 대신 11단계가 회수된 것을 거둔다 |
