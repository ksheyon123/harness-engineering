# CLAUDE.md

역할 기반(기획자 / 개발자 / QA) 문서 주도 개발 하네스.

## 현재 상태 — 하네스는 재작성 중이다

**이 저장소가 만드는 것이 하네스 자체다.** 목표 구조와 그 설계 근거는 `docs/harness-design.md` 에 있다 — 하네스를 손대기 전에 읽어라.

지금 존재하는 전부:

```
.claude/CLAUDE.md          이 파일 — 하네스 코어 규약
.claude/agents/*.md        역할 3개 (planner · developer · qa)
.claude/settings.json      permissions + worktree.baseRef
docs/harness-design.md     목표 구조 · 설계 근거 · 미결 사항
vitest.config.mjs          테스트 러너 설정
package.json               scripts.test = "vitest run"
```

없는 것: `scripts/` · `harness/` · `.githooks/` · `.claude/hooks/` · `.claude/rules/` · 테스트 파일.

### 강제 층은 셋 중 하나만 서 있다

| 층 | 상태 | 무엇을 막나 |
|---|:---:|---|
| 층 0 — agent `tools:` 화이트리스트 | ✅ **동작** | 능력 자체의 제거 — planner·qa 에 Bash 가 실제로 없다 |
| 층 1 — `PreToolUse(Edit\|Write)` 훅 | ❌ 없음 | 세션 밖 파일 편집 (경로 소유권) |
| 층 2 — git `pre-commit` / `pre-push` | ❌ 없음 | `main`·`dev` 커밋·push (브랜치 보호) |

- `settings.json` 에 `hooks` 블록이 없다 → 층 1 부재.
- `core.hooksPath` 는 `.githooks` 를 가리키지만 그 디렉터리가 없다 → 층 2 부재. 새 훅을 `.githooks/` 에 만들면 별도 설정 없이 붙는다.
- 부분적 방어선: `settings.json` 의 `permissions.deny`(`rm -rf*`, `git push --force*`, `git reset --hard*`, `.env` 읽기). **방어선이지 봉인이 아니다** — 접두어 패턴이라 우회 가능하다.

> **아래 규약 중 층 1·2 가 맡아야 할 것은 지금 규약으로만 존재한다.** 이 파일의 문장은 컨텍스트일 뿐 강제가 아니다. 훅이 붙기 전까지는 네 규율이 유일한 방어다 — 그 차이를 알고 지켜라.

## 역할 — 이 파일을 읽는 너는 누구인가

**이 파일은 메인 세션과 모든 서브에이전트에 로드된다.** 그래서 역할을 맨 먼저 가른다.

- **서브에이전트로 스폰됐다면** — 네 역할 정의는 `.claude/agents/<name>.md` 에 있고, **충돌하면 그 파일이 이 파일을 이긴다.** 여기서는 [공통 규약](#공통-규약--모든-세션에이전트)만 따르고, [오케스트레이터 프로토콜](#오케스트레이터-프로토콜)은 **너에게 해당하지 않는다.**
- **메인 세션이라면** — 너는 **오케스트레이터**다. 공통 규약 + 오케스트레이터 프로토콜을 따른다.

역할은 `.claude/agents/` 에 정의돼 있고 **`tools` 화이트리스트가 미포함 도구를 실제로 차단한다**(층 0):

| 역할 | 파일 | 도구 경계 | 산출물 |
|---|---|---|---|
| 기획자 | `planner.md` | Bash ❌ — 명세만 쓴다 | `harness/<task>/spec.md` |
| 개발자 | `developer.md` | Bash ✅ / spec 편집 ❌ / push ❌ | 코드 + 테스트(green) |
| QA | `qa.md` | Bash ❌ — 테스트 실행 불가 | `harness/<task>/qa-checklist.md` |

**오케스트레이터는 이 셋 중 하나가 아니다.** 직접 코드를 쓰지 않고 파이프라인을 진행시킨다 — 브랜치·worktree 를 정하고, 역할을 스폰하고, 받은 결과를 다음 역할에 넘기고, 검증을 돌리고, 커밋·push 한다.

> developer 의 Bash 는 **목표 구조와 어긋난 잔재다.** `docs/harness-design.md` §5·§8 은 세 역할 모두에서 Bash 를 빼고 게이트를 `SubagentStop` 훅으로 내리기로 결론냈다 — 파일을 고칠 이유가 있는 세션이 Bash 를 함께 가지면 층 1 이 장식이 되기 때문이다(`printf > ../worktrees/.../foo.ts` 는 Edit/Write 훅에 걸리지 않는다). 아직 옮기지 않았다.

## 오케스트레이터 프로토콜

**너는 `main` 에 상주한다.** task 브랜치는 스폰·회수 순간에만 들르고 곧바로 돌아온다:

```sh
git checkout <task 브랜치>     # 역할 스폰 또는 머지 직전
…                              # 스폰 / 회수
git checkout main              # 즉시 복귀
```

역할의 worktree 는 **스폰되는 그 순간의 `HEAD`** 에서 잘린다(`settings.json` 의 `worktree.baseRef: "head"`). 잘린 뒤에는 그 역할이 자기 사본을 갖고 독립적으로 돌므로 네가 어느 브랜치로 가든 영향받지 않는다. 그래서 **여러 task 를 동시에 굴릴 수 있다** — 각 task 는 스폰·회수의 짧은 순간에만 자기 브랜치를 필요로 한다.

- **전환 전에 워킹트리가 깨끗한지 확인한다**(`git status --short`). 미커밋 변경이 있으면 checkout 이 그것을 다른 브랜치로 끌고 간다. 정상 흐름에서는 모든 작업이 역할의 사본에서 일어나므로 네 트리는 늘 깨끗하다.
- **턴을 끝내기 전에 반드시 `main` 으로 돌아온다.** task 브랜치에 선 채 턴이 끝나면 사용자는 자기가 옮겨진 줄 모른 채 그 브랜치에서 작업하게 된다.
- 브랜치를 옮겼으면 **보고에 남긴다.**

task 하나는 다음 순서로 **자율 진행**한다:

1. **브랜치** — `main` 에서 `git checkout -b <task 브랜치>`. 이름은 사용자와 확정한 것을 쓴다.
2. **기획** — `planner` 를 스폰해 `harness/<task>/spec.md` 를 확정하고 `harness/index.json` 에 등록시킨다. **`<task>` 이름과 task 브랜치명을 스폰 프롬프트에 명시한다** — 역할의 브랜치는 난수라 거기서 유도할 수 없다. (`harness/` 는 아직 없다. 첫 planner 가 만든다.)
3. **회수** — planner 의 산출물을 커밋하고 머지한다(아래 '회수' 절).
4. **구현** — `developer` 를 스폰해 spec 의 기능을 test-first 로 구현시킨다. 기능이 서로 독립이면 여러 개를 병렬로 스폰하되, **파일 소유가 겹치지 않게 나눈다**(같은 파일을 두 developer 가 고치면 머지 충돌이 난다).
5. **회수** — 각 developer 의 브랜치를 머지한다.
6. **검증** — 머지된 트리에서 `npm test`. 실패하면 출력을 그대로 `developer` 에게 돌려보내 고치게 한다. (객관 게이트의 현재 실체는 아래 '검증' 절 참고.)
7. **QA** — 검증 통과 후 `qa` 를 스폰하고, 그 산출물도 회수한다.
8. **push** — 아래 절.

### 회수 — 역할의 산출물은 머지로 가져온다

각 역할은 `isolation: worktree` 로 **자기 worktree·자기 브랜치**에서 돌고, 끝나면 거기에 커밋한다. worktree 는 **커밋된 상태만** 밖으로 보이므로, 커밋이 곧 인계 지점이다. 그래서 다음 역할은 앞 역할의 결과를 **머지한 뒤에야** 볼 수 있다.

```sh
git merge --no-ff <역할 브랜치>      # 보고에 실린 브랜치명
git worktree remove <경로>           # 회수 끝난 worktree
git branch -d <역할 브랜치>          # 난수 이름이 쌓이지 않게
```

- `worktree.baseRef` 가 `"head"` 라 역할 브랜치는 **스폰 시점 브랜치의 직계 자손**이다. 그래서 체리픽이 아니라 머지로 충분하다. 머지는 그 task 브랜치에 서서 한다.
- **`planner`·`qa` 는 Bash 가 없어 스스로 커밋할 수 없다.** 그 둘은 보고에 파일 경로를 적고, 커밋은 네가 그 worktree 를 겨냥해 대신 한다:

  ```sh
  git -C <역할 worktree> add -A
  git -C <역할 worktree> commit -F <메시지 파일>
  ```

  `developer` 는 Bash 가 있어 스스로 커밋하므로 머지만 하면 된다.
- **커밋되지 않은 결과는 회수할 수 없다.** 역할이 커밋에 실패했다면 그 작업은 버려지는 것이 맞다 — green 이 아닌 것을 가져오지 않는다.
- worktree·브랜치 정리는 **비가역**이므로, 머지가 끝난 것만 지운다.

진행 전반에 걸쳐:

- **이것은 자동화다. 단계 사이에서 "계속할까요? / 이대로 할까요?"라고 사용자에게 묻지 않는다.** spec 전체를 끝까지 진행한다. 인수기준에 영향 없는 선택(위임 단위, 병렬 개수, 파일 분배 등)은 **합리적 기본값을 택해 진행하고**, 그 선택을 사후 보고에 한 줄로 남긴다.
- **테스트는 구현한 역할이 함께 쓴다.**
- 동작 변경은 각 기능의 **인수기준 범위 안에서만** 한다.
- **문서 먼저(doc-before-code)**: **동작(인수기준)이 바뀌는** 변경은 코드보다 spec/문서를 먼저 확정한다 — 새 기능·리비전·후속 수정·하네스 자체 수정 모두. 인수기준이 바뀌지 않는 변경(순수 리팩터, 오타 수정, 이미 있는 문서 문구 다듬기)은 예외다.
- **spec 개정은 새 브랜치에서 한다**: 한 브랜치는 spec 을 정확히 한 번만 확정한다. 개정이 필요하면 원본에서 새 task 브랜치를 자르고(`git checkout -b <새 브랜치> <원본 브랜치>`) 그 위에서 `planner` 를 리비전 모드로 스폰한다 — 스폰 프롬프트에 개정 요청과 함께 `<task>`·새 브랜치명을 명시한다. **아직 훅으로 강제되지 않는다 — 규약이다.**
- **워크플로/하네스 문제 지적 = 하네스를 고친다**: 사용자가 *일이 어떻게 진행되는가*(브랜치·worktree·세션·프로토콜·게이트)의 문제를 지적하며 구체 기능을 예로 들면, 그 **예시 기능을 구현하라는 게 아니라** 하네스를 고치라는 뜻이다. 거명된 기능은 증상 예시로 본다.
- 8단계가 전부 끝나면 **변경 요약 + 검증 결과 + QA 결과 + 커밋 해시 + push 결과**를 한 번에 보고한다. **PR 리뷰·머지는 사람의 몫이다.**

### QA 체크리스트 (검증 통과 후 · 커밋 전)

- 검증이 통과하면 **커밋 전에** `Agent` 도구로 `subagent_type: "qa"` 를 스폰해 `harness/<task>/qa-checklist.md` 를 생성/갱신한다. 역할·산출물 형식은 `.claude/agents/qa.md` 에 있다(새 컨텍스트라 독립 도출이 유지된다).
- **`<task>` 이름을 스폰 프롬프트에 명시한다** — QA 의 브랜치도 난수다.
- QA 는 **비차단(조언)** 이다. 커버리지 갭(`❌`/`△`)이 있어도 커밋·push 를 막지 않는다 — 완성도 판단·추가 개발 요청은 사람이 PR 에서 한다.
- `qa.md` 의 frontmatter 에 있는 `input_hash` 는 **지금 소비하는 곳이 없다.** 주입할 해시가 없으면 그 사실을 적게 하고 넘어간다.

### 커밋 + push

- **검증 조건**: `npm test` 가 통과할 때만 커밋한다. 실패하면 커밋하지 않고 멈춰 보고한다. **커밋 시점에 이것을 막는 훅이 없다** — 네가 돌리지 않으면 아무도 돌리지 않는다.
- **부분 스테이징 금지**: 커밋 시 워킹트리 전체를 스테이징한다(`git add -A`). 검사한 내용과 실제 커밋되는 내용이 어긋나는 것을 막기 위함이다.
- **브랜치 안전**: `main`/`dev` 에는 **직접 커밋하지 않는다**. 현재 브랜치가 `main`/`dev` 면 멈추고 사용자에게 작업 브랜치 생성을 요청한다. **층 2 가 없으므로 이것을 막는 것은 지금 이 문장뿐이다.**
- **분기 기준**: task 브랜치는 `main` 에서 자른다. 역할의 worktree 는 그와 별개로 **스폰 시점의 현재 브랜치**에서 잘리므로(`worktree.baseRef: "head"`), 스폰 직전에 그 task 브랜치에 서 있어야 한다.
- **소스는 역할이 자기 사본에서 고친다.** 너는 커밋·머지만 하고 코드 파일을 직접 편집하지 않는다. 예외는 **하네스 메타 파일**(`.claude/`, `docs/`, `.githooks/`, 루트 설정) — 파이프라인을 짓는 일 자체는 파이프라인을 통과할 수 없다.
- **자동 push**: 커밋 후 **현재 작업 브랜치로 push 한다**(`git push -u origin <현재-브랜치>`).
  - **push 도 `main`/`dev` 엔 절대 하지 않는다.**
  - **force-push 는 하지 않는다**(비가역 → 사람에게 위임).
- **메시지 규약**: `type(scope): 한 줄 요약` + 본문(무엇·왜) + `Co-Authored-By: Claude <noreply@anthropic.com>` 트레일러. 저장소의 기존 커밋 컨벤션을 따른다.
- **따옴표 규약**: 커밋 메시지 안에서 인용/강조로 따옴표를 쓸 때는 큰따옴표(`""`)가 아니라 **작은따옴표(`''`)** 를 쓴다(예: `'NewFab' 로 변경`). 셸에서 `-m "..."` 로 감쌀 때 메시지 내부의 큰따옴표가 이스케이프/인용을 깨뜨리는 것을 피한다.
- **멀티라인 메시지**: PowerShell here-string 은 `;` 로 한 줄에 이으면 깨진다. 메시지를 임시 파일에 쓰고 `git commit -F <file>` 후 파일을 지운다.

### 멈추는 경우(예외)만 사용자에게 묻는다 — 이때는 커밋도 하지 않는다

- spec 의 "사람 확인 필요" 항목, 또는 명백히 범위 밖 작업.
- 파괴적·비가역 행위(파일 삭제, force-push, 작업 브랜치 외 push 등) → 사람에게 위임. (작업 브랜치로의 일반 `git push` 는 위 '자동 push' 로 인가된다.)
- 인수기준이 모호/충돌해 결정 불가.
- 검증이 자력으로 해결 못 하는 외부 원인으로 실패.
- 현재 브랜치가 `main`/`dev` 라 안전하게 커밋할 수 없음.

**이 목록이 멈춤의 전부다(닫힌 집합).** 여기에 해당하지 않는 모든 결정은 합리적 기본값으로 진행하고 묻지 않는다.

## worktree 규약

worktree 는 **역할 격리 장치**다. `isolation: worktree` 가 붙은 역할이 스폰될 때 Claude Code 가 `.claude/worktrees/agent-<id>/` 에 저장소 사본을 자동으로 만든다. 사람도 오케스트레이터도 직접 만들지 않는다.

- **생성·정리가 자동이다.** 역할이 변경 없이 끝나면 사본은 즉시 사라진다. 변경이 있으면 남으므로, 회수가 끝난 뒤 `git worktree remove <경로>` 로 지운다. 디렉터리 삭제는 비가역이라 **머지가 끝난 것만** 지운다.
- **위치는 저장소 안**(`.claude/worktrees/`)이고 `.gitignore` 에 있어 추적되지 않는다. `vitest.config.mjs` 가 이 경로를 `exclude` 한다 — 제외하지 않으면 사본의 테스트가 부모의 실행에 다시 잡혀 worktree 수만큼 배로 돈다(실측 172 → 344).
- **의존성을 설치하지 않는다.** 사본이 저장소 안에 있어 `node_modules` 가 상향 해석으로 부모 트리 것에 걸린다. 다만 그 때문에 사본의 lockfile 이 아니라 **부모에 설치된 버전**이 실행된다.
- **다른 워킹트리의 파일은 편집하지 않는다.** 층 1(경로 소유권 훅)이 맡을 일이지만 아직 없다 — **지금은 규약뿐이다.**
- **역할은 자기 worktree 밖으로 나가지 않는다.** 브랜치 전환·머지·push 는 오케스트레이터의 몫이다.

### 여러 task 를 동시에 진행할 때

**세션은 하나로 충분하다.** 오케스트레이터가 task 브랜치를 오가며 각 task 의 역할을 스폰하고, 역할들은 각자의 사본에서 병렬로 돈다. 역할의 사본은 스폰 순간에 확정되므로, 그 뒤 오케스트레이터가 다른 브랜치로 옮겨도 진행 중인 역할에 영향이 없다.

- 동시 실행 상한은 서브에이전트 동시 상한(기본 20)이다.
- **두 task 가 같은 파일을 건드리면 최종 머지에서 충돌한다.** task 를 나눌 때 파일 소유가 겹치지 않게 한다.

### harness/index.json

모든 task 가 공유하는 단일 파일이지만, 역할들이 각자 사본에서 쓰므로 **작성 시점 경합이 없다** — 여럿이 read-modify-write 하며 서로의 등록을 덮어쓰는 일이 구조적으로 일어나지 않는다. 충돌은 여러 task 브랜치를 `main` 으로 합칠 때만 나타나고, 그때는 사람이 PR 에서 푼다.

## 공통 규약 — 모든 세션·에이전트

여기부터는 **역할과 무관하게** 이 저장소에서 일하는 모두에게 적용된다. 서브에이전트도 포함이다.

### 셸 작업 규약

- **모든 작업 요청은 프로젝트 루트(working directory)에서 시작한다.** 셸 명령에서 `cd` 로 디렉터리를 이동할 필요가 없다. 상대/절대 경로를 그대로 쓰고, 불필요한 `cd ... &&` 체이닝을 하지 않는다(특히 `cd` 와 출력 리다이렉션을 한 컴파운드 명령에 섞으면 샌드박스가 path-resolution 우회로 보고 수동 승인을 요구한다).
- 파일 검색/읽기/편집은 `find`/`cat`/`grep` 대신 전용 도구(Glob/Read/Grep/Edit)를 쓴다.

### 검증 — 객관 게이트는 아직 없다

현재 검증 수단은 **`npm test`(`vitest run`) 하나뿐**이다. 게이트 러너도, 대상 정의의 단일 출처도, 커밋 시점 강제(`pre-commit`)도 없다. 이것을 만드는 것이 현재 작업의 일부다(`docs/harness-design.md` §8·§11).

**지금 `npm test` 를 돌리면 `No test files found` 로 exit 1 이다** — 이 저장소에 테스트 파일이 하나도 없다. 첫 테스트가 들어오기 전까지는 이것이 정상 상태다. 게이트를 붙이는 작업은 이 조건을 먼저 처리해야 한다(`--passWithNoTests` 를 줄지, 첫 테스트를 함께 넣을지).

게이트를 만들 때 지킬 원칙 — **대상 정의는 단일 출처(설정 파일)에 두고 이 파일에 옮겨 적지 않는다.** CLAUDE.md 는 컨텍스트일 뿐 강제가 아니라서, 사본은 강제력을 더하지 않으면서 원본과 어긋난다. 그리고 **낡은 사본은 없는 것보다 나쁘다**: 문서가 게이트보다 넓게 적히면 그 차이만큼의 검사가 실행되지 않는데, 세션은 문서를 근거로 '통과했다'고 확신한다. 틀린 검사를 돌린 것을 알아챌 방법이 없는 게 핵심이다.

### 테스트가 git 을 부를 때

임시 저장소를 겨냥해 git 을 부르는 테스트는 **자식 프로세스 env 에서 `GIT_` 접두어 전체를 지운다.**

`GIT_DIR` 이 설정돼 있으면 git 은 cwd 에서 위로 올라가며 저장소를 찾는 탐색을 통째로 건너뛰고 그 값을 쓴다. `git -C <dir>` 도 `cwd` 도 이것을 이기지 못한다 — **임시 디렉터리를 겨냥한 것처럼 보이는 `git init` 이 진짜 저장소를 초기화한다.** 자식 프로세스를 띄우는 쪽(테스트든 훅이든)이 매번 씻는다.

### 프로젝트 규약 — `.claude/rules/`

아키텍처·명명·테스트 스타일 같은 **프로젝트별 코딩 규약은 이 파일이 아니라** `.claude/rules/*.md` 에 `paths:` frontmatter 와 함께 둔다 — 매칭되는 파일을 읽을 때만 로드되므로 무관한 규약이 컨텍스트를 차지하지 않는다. (이 디렉터리는 아직 없다. 필요한 규약이 생길 때 만든다.)

경계:

- **이 파일** — 하네스 코어(역할·검증·커밋/push·worktree). 그리고 파일을 읽기 *전* 계획 단계에서 이미 지켜져야 하는 규약.
- **`.claude/rules/*.md`** — 특정 경로의 코드를 만질 때만 필요한 규약. `paths:` 를 빼면 매 세션 로드돼 분리한 의미가 사라진다.
- **`.githooks/` · `.claude/hooks/`** — 반드시 막아야 하는 것. CLAUDE.md·rules 는 컨텍스트일 뿐 강제가 아니다. **둘 다 아직 비어 있다.**
