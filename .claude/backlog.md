# 하네스 백로그 — 확인됐지만 아직 안 고친 것

**읽는 주체는 실행자다.** 하네스를 손대러 맨몸 `claude` 를 열었을 때 여는 문서이고, 그 외에는 아무도 읽지 않는다. `CLAUDE.md` 의 미착수 표가 *무엇이* 안 됐는지를 한 줄로 적는다면, 여기는 *왜 그게 문제이고 어떻게 고치는지*를 적는다.

> **쓰기만 하고 아무도 안 읽는 파일은 틀려도 아무도 모른다.** `harness/index.json` 이 그렇게 죽었다. 이 파일도 같은 위험을 진다 — **항목을 고쳤으면 여기서 지워라.** 남겨두고 "완료" 라고 적지 마라. 지워지지 않는 백로그는 곧 아무도 안 믿는 백로그가 된다.

각 항목은 **증상 → 근거 → 어떻게 → 어디를 만지나** 순서다. 근거는 전부 소스나 실측이고, 추측인 것은 그렇게 적었다.

---

## A — `pre-commit`: 한 브랜치에 spec 은 하나

**증상.** 한 작업 세션이 두 번째 task 를 받아도 막는 것이 없다. `ExitWorktree` 없이 이어가면 두 task 의 spec 이 한 브랜치에 쌓이고 **한 PR 로 나간다.**

**근거.** 층 1 은 작업 세션의 `harness/**` 를 `defer` 로 통과시킨다(자기 산출물이 맞다). `pre-commit` 의 `spec-shape` 는 스테이징된 spec 의 *형식*만 본다 — frontmatter·`branch:`·`## 기능 목록`. 두 번째 spec 이 형식만 맞으면 그대로 커밋된다. `CLAUDE.md` 는 "한 브랜치는 spec 을 정확히 한 번만 확정한다"고 적어놓고 **"아직 훅으로 강제되지 않는다 — 규약이다"** 라고 스스로 인정한다.

**어떻게.** `pre-commit` 에서 이 브랜치가 추가한 spec 을 센다:

```
git diff --name-only <merge-base>...HEAD -- 'harness/**/spec.md'   →  둘 이상이면 거부
```

주의할 것 셋:

- **기준을 `main` 으로 박지 마라.** `dev` 기반 브랜치에서 틀린다. `git merge-base` 로 잡는다.
- **3점(`...`)이어야 한다.** 이미 base 에 있던 spec 은 세면 안 된다.
- **리비전 모드는 걸리지 않는다.** 기존 spec 을 고치는 것은 파일이 하나라 통과한다 — 의도한 대로다.

**어디.** `.githooks/pre-commit.mjs` + `.githooks/pre-commit.test.mjs`. 코드 변경이라 B·C·E·F 와 섞지 말고 따로 간다.

## B — 병렬 `developer` 를 기본에서 예외로 내린다

**증상.** `CLAUDE.md` 5단계가 "기능이 독립이면 병렬로 스폰하되 파일 소유가 겹치지 않게 나눈다"로 병렬을 권한다. 그런데 오케스트레이터에게는 겹치는지 판단할 근거가 없고, 어긋났을 때의 복구 경로가 실행 불가능하게 적혀 있다.

**근거 1 — 병렬 가능한 집합이 애초에 좁다.** `planner-mode.md` 의 task 경계 기준은 "파일이 겹치면 묶는다 · 순서 의존이 있으면 묶는다"다. 병렬 조건은 정확히 그 반대(안 겹치는 것만 나눈다). 남는 것은 **세 번째 기준(한 PR 로 나가야 한다)으로만 묶인 기능들**뿐이다. 있긴 하지만 다수가 아니다.

**근거 2 — 판단 근거가 spec 에 없다.** `## 기능 목록` 항목은 의도·방식·주의·인수기준이고 **파일 소유가 없다.** 코드가 아직 없는 시점에 기능 이름만 보고 추측해서 나누는 셈이다.

**근거 3 — 이게 결정적이다. 통합 red 를 고칠 자리가 없다.**

- 통합 red 는 **머지된 트리에서만** 보인다
- `developer` 의 worktree 는 **머지 이전** 커밋에서 잘렸다. 다른 developer 의 코드가 없다
- 거기서 고치면 그 종료 게이트는 **다른 구현이 없는 트리**에서 `npm test` 를 돌린다 — green 이 나고 종료되는데 머지 트리는 여전히 red. **게이트가 엉뚱한 트리를 검증한다**
- A 의 브랜치에 B 를 넣을 수도 없다: 격리 세션은 남의 worktree 를 건드릴 수 없고, 다른 worktree 에 체크아웃된 브랜치는 업데이트가 거부된다

그래서 실제 복구는 **머지된 HEAD 에서 새 `developer` 를 스폰하는 것**뿐이다(`worktree.baseRef: "head"` 라 새 사본에 두 구현이 다 들어온다). 그 새 컨텍스트는 두 구현을 모른다 — 병렬로 아낀 시간을 여기서 토해낸다.

**순차의 이득.** A 회수 → 그 HEAD 에서 B 스폰. B 의 worktree 에 A 코드가 이미 있으므로 **B 의 종료 게이트가 곧 통합 검증**이 된다. 7단계가 공짜로 강해진다. 잃는 것은 벽시계 시간뿐이다.

**어떻게.**

- 5단계를 **순차 기본**으로 뒤집는다. 병렬은 "spec 이 파일 소유를 명시해 겹치지 않음이 확인될 때만" 으로 내린다
- 7단계의 "실패하면 출력을 그대로 `developer` 에게 돌려보낸다" 를 실행 가능한 지시로 교체한다 — **머지된 HEAD 에서 새 `developer` 를 스폰**하고, 실패 출력과 함께 두 구현을 다 읽으라고 준다

**어디.** `.claude/CLAUDE.md` 의 오케스트레이터 절.

**딸린 선택지(별건).** spec 의 기능 항목에 "**건드릴 파일**" 을 추가하면 병렬 판단에 근거가 생긴다. 다만 spec 형식 변경이라 `spec-shape.mjs` 도 같이 봐야 하고, 코드가 없는 시점에 파일을 적는 것이 얼마나 정확할지도 미지수다. **B 를 먼저 하고 필요해지면 그때 판단한다.**

## C — "한 세션 = 한 작업" 자기모순

**증상.** `CLAUDE.md` 가 같은 것을 두 번, 다르게 말한다.

| 어디 | 뭐라고 |
|---|---|
| 작업 세션 절 첫 줄 | "**한 세션 = 한 작업**이고, 끝나면 닫는다" |
| 오케스트레이터 절 끝 | "task 가 여럿이면 `ExitWorktree(keep)` 후 다음 task 로 다시 `EnterWorktree` — **순차가 기본이다**" |

두 번째 문장이 한 세션의 다중 task 를 **정식 경로로 인정한다.**

**근거 — 어느 쪽으로 정하느냐가 결과를 바꾼다.** 다중 task 를 인정하면 `planner-mode.md` 의 완결성 압력이 거짓이 된다: "세션은 끝나면 닫힌다. **spec 에 안 적힌 것은 없는 것이다.**" 안 닫히면 세션이 이전 task 의 논의를 기억하고 있어서, 얇은 spec 을 쓰고 나머지를 스폰 프롬프트로 메울 수 있다. 이 하네스가 막으려는 바로 그 실패다.

**어떻게.** **한 세션 = 한 task 로 못 박고** 다중 task 문장을 지운다. A 가 그것을 훅으로 받쳐준다(같은 브랜치에 두 spec 이 못 쌓인다). 그리고 못 막는 것을 미착수 표에 정직하게 올린다:

- **실행자가 원문 대신 요약을 실어 넘기는 것** — 못 막는다. 요약과 원문은 문자열로 구분되지 않고, "사람이 실제로 논의했는가" 는 훅이 판정할 수 있는 종류가 아니다. 실리면 기획자 모드가 형식적으로 지나가고 사실상 오케스트레이터로 직행한다
- **작업 세션끼리 파일 소유가 겹치는지** — 이미 표에 있다. 각 spec 이 자기 worktree 안에만 있어 기획자 둘이 서로를 못 본다

**어디.** `.claude/CLAUDE.md`. E·F 와 인접 문단이라 한 브랜치로 묶는다.

## E — 회수 근거를 "보고"에서 조상 질의로

**증상.** 오케스트레이터가 머지할 브랜치명을 얻는 경로가 **문서상 비어 있다.**

| 어디 | 뭐라고 |
|---|---|
| `CLAUDE.md` 회수 절 | `git merge --no-ff <역할 브랜치>` — "보고에 실린 브랜치명" |
| `developer.md` 보고 항목 6개 | 기능·파일·테스트·게이트·판단·막힌 것 — **브랜치명 없음** |
| `qa.md` 보고 항목 4개 | 파일·요약·볼 것·판정 못한 것 — **없음** |
| `developer.md` 입력 절 | "네 브랜치는 `worktree-agent-<난수>` 라 …**확인할 수단도 없다**" |

읽으라는 것을 아무도 쓰지 않고, 쓸 주체에게는 알 수 없다고 말해놨다. 회수가 "✅ 검증됨"으로 적혀 있지만 **그때 어느 경로로 이름을 얻었는지는 기록이 없다.**

**어떻게 — 이름 대신 조상으로 찾는다.**

```
git branch --list 'worktree-agent-*' --contains <내 spec 커밋 sha>
```

`worktree.baseRef` 가 `"head"` 라 내 에이전트의 브랜치는 **내 브랜치의 직계 자손**이다. 다른 작업 세션의 에이전트는 그 세션 브랜치에서 잘렸으므로 내 spec 커밋을 포함하지 않는다. spec 커밋 sha 는 내가 직접 만든 것이라 확실히 안다 — **스냅샷도 필요 없고 동시 스폰 race 도 없다.**

**어디.** `.claude/CLAUDE.md` 회수 절. 그리고 `developer.md`·`qa.md` 의 "확인할 수단도 없다" 문장 정리 — 보고에 요구하지 않을 거면 그 서술 자체를 빼는 게 맞다.

**부수 사실(규약으로 올리지 않는다).** 에이전트는 Bash 없이도 자기 브랜치를 알 수 있다 — `.git` 파일(`gitdir: …`)을 Read 하고 그 경로의 `HEAD` 를 Read 하면 `ref: refs/heads/worktree-agent-<id>` 가 나온다. 층 1 은 `Edit|Write` 만 보므로 Read 는 막히지 않는다. **다만 경로 구조에 의존하는 2단계 읽기라 취약하다.** 오케스트레이터 쪽 질의가 훨씬 튼튼하니 그쪽만 쓴다.

## F — 회수 전 확인을 worktree 가 아니라 브랜치로 한다

**F 의 원래 지적은 실측으로 틀렸다.** "`handoff` 가 성공하면 트리가 깨끗해져 오히려 정리 대상이 된다" 고 추측했었는데, 실제로는 **인계 커밋이 있으면 Claude Code 가 지우지 않는다** — 실측 시점에 죽은 사본 4개가 남아 있었다. "반드시 남는다" 는 문장이 맞았다.

그래서 남은 것은 하나뿐이다.

**증상.** `CLAUDE.md` 회수 절이 확인의 근거를 **사본의 존재**에 둔다:

> red 여도 커밋은 되어 있으니 머지하지 않고 들여다볼 수 있다

**근거.** 이제 `reap-worktrees.mjs` 가 회수된 사본을 거둔다. 아직 회수 전이면 사본이 남아 있으므로 이 문장이 당장 틀리지는 않는다 — 다만 **확인의 근거를 사라질 수 있는 것에 두고 있다.** 브랜치 ref 로 물으면 사본이 있든 없든 같은 답이 나온다.

**어떻게.** `git show <역할 브랜치>` / `git diff <내 브랜치>...<역할 브랜치>` 로 바꾼다. E 의 조상 질의와 정확히 같은 방향이다.

**어디.** `.claude/CLAUDE.md` 회수 절. E 와 묶는다.

## 실측으로 확인된 것 — 다시 재보지 마라

| 무엇 | 결과 |
|---|---|
| 본체에서 링크된 worktree 의 브랜치 `git branch -m` | **된다.** 그 worktree 의 `HEAD` 파일까지 따라 바뀐다 |
| 같은 브랜치 `git worktree move` | **된다** |
| 같은 브랜치 `git branch -D` | **거부된다** (`used by worktree at …`) |
| 격리된 worktree 안에서 `git worktree list` · `git branch --list` · 남의 브랜치 `git log` | **전부 된다.** `git -C <남의 트리>` 와 다르다 — 남의 워킹트리를 건드리지 않는 읽기다 |
| `git branch --list` 의 `+` 접두어 | **다른 worktree 에 체크아웃 중**이라는 표시 |
| 에이전트가 Bash 없이 자기 브랜치 알기 | **된다.** `.git` → `gitdir:` → 그 경로의 `HEAD`, Read 두 번 |
| `.claude/` 가 protected path 라 쓰기가 막히나 | **아니다.** `.claude` 는 보호 대상이지만 **`.claude/worktrees` 는 명시적 예외**다 |
| `defer` 가 유효한 `permissionDecision` 인가 | **유효하다.** `allow`·`deny`·`ask`·`defer` 넷 다. `defer` = '결정하지 않음' = 정상 권한 흐름 |
| 사후 rename 으로 `agent-<난수>` 를 정리하는 것 | **의미 없다.** 회수는 한 번 쓰고 버리는 이름이고, 동일성은 E 의 조상 질의로 푼다 |
| 인계 커밋이 찍힌 사본을 Claude Code 가 자동으로 지우나 | **안 지운다.** 죽은 사본이 계속 쌓인다 — `reap-worktrees.mjs` 가 생긴 이유다 |
| 자기가 서 있는 worktree 를 지우기 | **안 된다.** `failed to delete: Permission denied` (Windows 가 cwd 를 잡는다). 그 사본을 cwd 로 가진 **다른** 프로세스가 살아 있어도 마찬가지다 |
| 링크된 worktree 안에서 *다른* worktree `remove` | **된다** (순수 git 기준) |
| 사본을 지운 뒤 그 브랜치 머지 | **된다.** `worktree remove` 는 objects 도 refs 도 건드리지 않는다 |
| dirty · 미머지 · locked 사본을 `--force` 없이 지우기 | **셋 다 거부된다.** 정리의 안전장치가 전부 여기 걸려 있다 |

## 순서

**A 는 코드+테스트라 독립**이다. **B·C·E·F 는 `CLAUDE.md` 의 인접 문단**을 건드리므로 한 브랜치로 묶는 편이 낫다 — 따로 가면 서로 충돌한다.

이 문서에 없는 것: 실행자의 요약 전달(C 에서 "못 막는다"로 기재만 한다), spec 의 파일 소유 명시(B 의 딸린 선택지).
