# 작업 세션으로 넘긴다

인자로 받은 문자열을 **그대로** 실어 새 탭을 띄운다:

```
harness spawn "<인자 그대로>"
```

## 원문을 한 글자도 바꾸지 않는다

**요약하지 마라.** 요구사항 요약·결정 사항·"이렇게 하기로 했다"는 사람 머릿속에만 있어 작업 세션이 검증할 수 없고, **싣는 순간 spec 에 안 적히고 프롬프트로만 존재하게 된다.** 그러면 spec 이 그 요약 수준에서 멈추고, `qa` 는 그 불완전한 spec 과 테스트를 대조하고, 사람은 PR 에서 반쪽짜리 근거를 본다.

사람이 친 문자열이 그대로 인자로 들어가는 것이 이 스킬의 요점이다 — 요약이 끼어들 자리가 없다.

이미 논의를 받아버렸더라도 마찬가지다. **"그 논의는 작업 세션에서 다시 하라"** 고 안내하고 원문 수준으로만 넘긴다.

## 넘긴 뒤

새 탭은 `HARNESS_ROLE=work-session` 을 물고 열리고, 원문이 첫 프롬프트로 들어가 **탭이 열리는 순간 논의가 시작된다.** 논의는 거기서 한다 — 이 세션의 일은 끝이다.

Windows 에서 `wt` 가 없으면 새 창으로 떨어지고, macOS 는 애초에 새 창이다. 탭이든 창이든 **실행자와 다른 프로세스**인 것이 요점이다.

## 실패하면 알린다

`spawn` 은 **Windows 와 macOS 에서 돈다**(macOS 는 테스트 미완이다). 그 밖의 플랫폼에서는 없다고 말하고 종료 코드 1 을 낸다 — **조용히 넘어가지 않는다.** 그 신호가 오면 사람에게 알려라. 직접 `claude` 를 열어 역할을 말로 심는 것은 대안이 아니다: 그 세션은 `HARNESS_ROLE` 이 없어 자기를 실행자로 알고, 대화로 덮은 역할은 `/clear` 한 번에 사라진다.
