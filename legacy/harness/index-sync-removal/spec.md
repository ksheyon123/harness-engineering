# index-sync-removal

## 목적

`index-sync` 훅(Hook 3)을 **제거한다.** BACKLOG #5 는 이것을 "구현 작업이 아니라 판단"으로 남겨 뒀고, 판단은 제거로 확정됐다.

## 결정 근거

훅의 의도는 **코드→문서 드리프트 알림**이다. `harness/index.json` 의 `components` 에 코드 파일 ↔ 설계 문서 섹션을 매핑해 두고, 그 파일을 Edit/Write 하면 "대응 섹션도 갱신하라"고 컨텍스트에 알린다(`PostToolUse`, 차단 없음).

겨냥한 문제 자체는 실재한다. 이 저장소가 실제로 겪은 드리프트가 BACKLOG 에 세 건 있다 — `#1`(게이트 대상이 CLAUDE.md 와 pre-push 에 중복돼 어긋남), `#7`(CLAUDE.md 의 면제 의도와 코드 불일치), `#2`(qa.md 의 Phase 1 서술이 현실과 어긋남).

**그러나 이 저장소가 실제로 채택한 해법은 이 훅이 아니었다.** `#1` 의 결론은 *"강제되는 사실을 소프트 문서에 복사하지 말고 단일 출처로 모아라"* 였다. 드리프트를 **알림으로 따라잡는** 대신 **중복 자체를 없앤** 것이다. 후자가 더 근본적이다 — 알림은 무시할 수 있지만, 사본이 없으면 어긋날 것이 없다.

그리고 결정적으로, **이 훅은 한 번도 동작한 적이 없다.** `components` 가 `{}` 라 조회가 항상 실패해 즉시 `exit 0` 한다. 매핑을 **누가·언제 등록하는지가 프로토콜 어디에도 없다** — 설계 문서 §11 적용 순서에도, planner·QA·개발자 규약에도 없다. 분리 이전 저장소에서 80개 task 를 거치는 동안 매핑은 0개였다. 설계에서 빠진 것은 훅이 아니라 **그 훅을 먹여 살릴 절차**이고, 그 절차를 사람이 수동으로 유지하게 만들면 실제로는 계속 비어 있을 것이다.

남는 영역이 하나 있다: `harness-engineering.md` 같은 **서술형 설계 문서**는 코드로 대체할 수 없어 단일 출처로 모을 수 없다. 그 영역의 드리프트는 **사람이 PR 에서 잡는다**고 인정한다 — 하네스의 다른 부분과 같은 판단이다("사람 머지가 유일한 품질 게이트").

## 범위 밖 (명시)

- 드리프트 방지를 위한 **대체 장치 도입**. 이 task 는 제거만 한다. 필요가 다시 드러나면 그때 근거를 갖고 설계한다.
- `harness/index.json` 의 `tasks` 키. 그대로 둔다(`load-spec`·`verify-branch`·`pre-push`·`worktree-add` 가 쓴다).
- `#7`(verify-branch)·`#2`(Phase 1 서술) 작업. 별도 task.

## 기능 목록

### 기능: 훅과 등록을 제거한다

- **의도**: 죽은 코드가 살아 있는 것처럼 보이면, 다음 사람이 "드리프트는 훅이 잡아준다"고 잘못 믿는다.
- **방식**:
  - `.claude/hooks/index-sync.mjs` 삭제.
  - `.claude/settings.json` 의 `hooks.PostToolUse` 블록 제거. **`PostToolUse` 키 전체를 지운다** — 이 훅이 유일한 항목이라 빈 배열만 남기면 의미 없는 껍데기가 된다.
  - `harness/index.json` 의 `"components": {}` 키 제거.
- **주의**:
  - `settings.json` 은 JSON 이라 트레일링 콤마가 남으면 **Claude Code 가 설정 전체를 못 읽는다.** 편집 후 파싱을 확인한다.
  - `PostToolUse` 에 다른 훅이 나중에 붙을 수 있으나, 그때 다시 추가하면 된다. 빈 구조를 남겨두는 것이 친절해 보이지만 실제로는 "여기 뭔가 있었다"는 잘못된 신호다.
  - 삭제는 비가역이지만 **git 이 이력을 갖고 있다.** 되살릴 근거가 생기면 커밋에서 복원할 수 있음을 커밋 메시지에 남긴다.
- **인수기준**:
  - `.claude/hooks/index-sync.mjs` 가 존재하지 않는다.
  - `.claude/settings.json` 이 유효한 JSON 이고 `PostToolUse` 키가 없다.
  - `harness/index.json` 이 유효한 JSON 이고 `components` 키가 없다.
  - `node scripts/gate.mjs` 가 통과한다(다른 훅·스크립트가 `components` 를 참조하지 않음이 확인된다).

### 기능: 설계 문서에서 Hook 3 서술을 제거한다

- **의도**: 설계 문서가 존재하지 않는 훅을 "핵심 3훅 중 하나"로 서술하고 있으면, 그것이 다음 도입 프로젝트에 그대로 복제된다.
- **방식**: `harness-engineering.md` 에서 다음을 정리한다.
  - §4 디렉터리 구조 — `hooks/index-sync.mjs` 줄, `index.json` 설명의 "+ 컴포넌트 인덱스".
  - §7 표 — `.claude/settings.json` 담당에서 "Hook3 인덱스 동기화" 제거.
  - §7.2 절 전체 제거.
  - §8 `settings.json` 예시에서 `PostToolUse` 블록 제거.
  - §11 적용 순서 — 1번의 `components` 초기화, 3번의 `index-sync.mjs` 작성.
- **주의**:
  - **제거 사실과 이유를 문서 하단 '설계 변경 이력' 에 한 줄 남긴다.** 그냥 지우면 다음 사람이 같은 설계를 다시 제안한다. 이 저장소는 그 이력을 남기는 관례가 이미 있다.
  - `harness-engineering.md` 는 **`#2`(Phase 1 서술 제거)도 같은 파일의 §6·§7.3·§10·§11 을 고친다.** 두 task 가 §11 에서 겹치므로 **동시에 진행하지 않는다** — 이 task 를 먼저 머지하고 `#2` 를 그 위에서 진행한다.
- **인수기준**:
  - `harness-engineering.md` 에 `index-sync` 가 등장하지 않는다(변경 이력의 한 줄 제외).
  - §8 의 `settings.json` 예시가 실제 `.claude/settings.json` 과 일치한다.

### 기능: BACKLOG #5 를 완료로 정리한다

- **의도**: BACKLOG 가 결정 대기 상태로 남아 있으면 다음 세션이 다시 판단하려 든다.
- **방식**: #5 항목에 취소선 + **완료**, 채택한 결론(제거)과 근거 요약, 커밋 해시. 우선순위 표도 갱신한다.
- **인수기준**: BACKLOG #5 가 완료로 표시되고, 제거를 택한 이유가 항목 안에서 읽힌다.
