# 하네스 백로그 — 확인됐지만 아직 안 고친 것

**읽는 주체는 사람이다.** 하네스를 손볼 개발자가 "무엇이 남았나" 를 확인하러 여는 문서다. **안 된 것은 전부 여기 있다** — *무엇이* 안 됐는지와 *왜 그게 문제이고 어떻게 고치는지*를 같이 적는다.

> **쓰기만 하고 아무도 안 읽는 파일은 틀려도 아무도 모른다.** `harness/index.json` 이 그렇게 죽었다. 이 파일도 같은 위험을 진다 — **항목을 고쳤으면 여기서 지워라.** 남겨두고 "완료" 라고 적지 마라. 지워지지 않는 백로그는 곧 아무도 안 믿는 백로그가 된다.
>
> 한때 같은 목록이 `.claude/CLAUDE.md` 에도 있었다. 지웠다 — **사본은 강제력을 더하지 않으면서 반드시 어긋나고**, 하필 그 파일은 매 세션·매 서브에이전트에 로드돼 끝난 항목까지 모두의 컨텍스트를 먹었다.

각 항목은 **증상 → 근거 → 어떻게 → 어디를 만지나** 순서다. 근거는 전부 소스나 실측이고, 추측인 것은 그렇게 적었다. **이미 재본 것은 [`measured.md`](./measured.md) 에 있다 — 다시 재기 전에 거기부터 봐라.**

## G — 패키지화 이후 남은 것

**패키지화 자체는 끝났다.** `npm i -D @ksheyon123/harness-engineering` + `npx harness init` 으로 다른 저장소(이하 **A**)에 선다. `install/init.integration.test.mjs` 가 **발행되는 tarball 을 실제로 풀어 설치해서** 층 1·2 · worktree 안의 shim · `post-checkout` · `doctor` · `sync` · `smoke` · 재실행 멱등성까지 고정한다.

아래 다섯은 그 위에 남은 것이고 **서로 독립적이다** — 순서가 없다.

### G-1 사본 도달을 강제하는 자리가 없다

`init` 은 못 한다 — 남의 저장소에 커밋을 만들지 않으므로 갓 설치한 직후를 실패로 낼 수 없고, 그러면 종료 코드가 *항상* 1 이 되어 아무 정보도 아니게 된다. 강제할 것은 커밋이 아니라 **도달**이다(심기든 커밋이든 하나면 된다).

*어떻게.* 자리는 **`spawn`** 이다 — 작업 세션을 열기 전에 `smoke` 를 돌리고 초록이 아니면 탭을 안 띄운다. `scripts/spawn.mjs` 의 `plan` 에 선례가 있다(`claude` 를 PATH 에서 못 찾으면 탭을 띄우기 전에 죽는다). **맨몸 `claude`(실행자)는 막으면 안 된다** — 설치를 고치러 오는 유일한 자리라 막으면 순환이다.

### G-2 층 1 의 fail-closed

훅이 살아 있으면 나머지 미비는 전부 그것이 막을 수 있다 — `manifest` 경로가 디스크에 없으면 전부 deny. 사본에서는 **"존재하나"가 곧 "도달했나"** 라(커밋이든 심기든, 안 왔으면 없다), 위험한 자리(`developer`·`qa`)에서 그 질문이 `existsSync` 로 싸게 답해진다. 매 `Edit`/`Write` 마다 도는 자리라 `smoke` 전체를 돌릴 수는 없다. *어디* — `.claude/hooks/path-ownership.mjs`.

### G-3 훅의 실행권한이 POSIX 에서 검증된 적이 없다

`npm pack` 이 워킹트리를 떠서 `.githooks/*` 가 `644` 로 발행되고(실측), **git 은 실행권한 없는 훅을 에러 없이 건너뛴다** — A 의 POSIX 환경에서 층 2 가 통째로 없는데 아무도 모른다. `init` 이 `chmod 0o755` 로 되돌리고 `smoke` 가 실행 비트를 보지만, **둘 다 Windows 에서는 확인이 안 된다**(`makeExecutable` 은 실패를 삼키고, `smoke` 는 `?` 를 찍는다). *어떻게* — POSIX 에서 돌려야 한다. CI 없이는 안 켜진다.

### G-4 충돌 전수(survey) 가 좁다

지금 `plan` 은 **아는 충돌**만 본다(`core.hooksPath` · `baseRef` · JSON 파싱). 하네스가 쓸 모든 경로에 대해 "이미 있나 · 누가 소유하나" 를 일괄로 묻는 데까지 넓히면, A 자신의 `.claude/hooks/*.mjs`·`agents/*.md` 와의 **이름 충돌**이 드러난다 — 지금은 조용히 덮는다. *어디* — `install/init.mjs` 의 `plan`.

### G-5 `.harness/` 이주 — 방향부터 정해야 한다

`.claude/` 아래 것들 중 Claude Code 가 그 자리를 *요구하는* 것은 `settings.json` 과 `agents/*.md` 뿐이다. 나머지는 하네스가 고른 자리다 — 훅 경로는 `settings.json` 이 절대 지정하고, `@` 임포트는 프로젝트 루트 안이면 어디든 된다. 논거는 **A 가 `.claude` 를 무시한 판단은 옳은데**(개인 설정이라고 본 것이다) **하네스 파일은 팀 규약이라 거기 있는 것이 의미상 틀렸다**는 것이고, 이름 충돌(G-4)도 같이 사라진다.

**다만 최근에 반대로 움직였다** — 설정이 `.claude/harness.config.json` 으로 들어갔다(`plant.mjs` 에 구 위치 fallback 이 남아 있다). 그리고 심기가 gitignore 문제를 이미 풀어서 원래 동기의 절반이 사라졌다. **이주할지부터 다시 정한다.**

## H — G 밖에 남은 구멍

한때 `.claude/CLAUDE.md` 의 미착수 표에 한 줄씩 있던 것들이다. 둘로 갈린다 — **고칠 예정인 것** 하나와 **막을 수 있지만 대가가 더 큰 것**들. 뒤엣것은 고칠 대상이 아니라 **알고 있어야 하는 것**이라, 끝나도 지워지지 않는다는 점에서 G 와 성격이 다르다.

### H-1 고칠 예정

**macOS 의 `spawn` 이 한 번도 실행된 적이 없다.** 정책(저장소 찾기 · `claude` 찾기 · 원문 조립)은 `scripts/spawn.mjs` 로 올라와 플랫폼을 안 가리고, macOS 는 일회용 `.command` 스크립트를 `open -a Terminal` 로 여는 데까지 코드가 서 있다. **검사되는 것은 명령 본문까지다**(`scripts/spawn.test.mjs` 가 역할·저장소·원문·따옴표를 고정한다). 검사된 적 없는 것은 그 뒤 한 걸음 — **`open` 이 실제로 창을 띄우고 그 창의 `claude` 가 `HARNESS_ROLE` 을 물고 뜨는가.** 개발 기계가 Windows 라 여기서는 잴 수 없다.

*어떻게.* Mac 에서 `harness spawn --dry-run "x"` 로 겨냥한 자리를 먼저 보고, 그 다음 진짜로 띄워 **새 창의 세션이 자기를 작업 세션으로 선언하는지** 확인한다. 걸릴 만한 자리는 셋이다 — Terminal 이 `.command` 를 실행 비트 없이 거부하는가(`0700` 으로 쓴다), 로그인 셸의 PATH 가 달라 `claude` 절대경로가 안 맞는가(그래서 절대경로로 박는다), `open` 이 종료 코드 0 을 주고도 아무것도 안 여는가. **G-3(POSIX 실행권한)과 같은 기계가 필요하다** — 둘을 한 번에 재는 것이 맞다.

**Linux 판은 아예 없다.** 터미널이 제각각이라(`tmux new-window` · `gnome-terminal --tab` · `konsole`) 하나를 고를 근거가 없고, **쓸 사람이 아직 없다.** 필요해지면 `spawn.mjs` 의 `launch` 에 한 갈래를 더한다 — 정책은 이미 공유되므로 더할 것은 "터미널을 어떻게 여는가" 하나뿐이다. 그 전까지는 없다고 말하고 종료 코드 1 을 낸다(직접 `claude` 를 여는 것은 대안이 아니다 — `HARNESS_ROLE` 이 없어 그 세션은 자기를 실행자로 알고, 말로 덮은 역할은 `/clear` 한 번에 사라진다).

### H-2 막을 수 있지만 대가가 더 크다 — 규율에 맡긴 것

| 무엇 | 지금 어디까지 막히나 | 왜 더 안 막나 |
|---|---|---|
| 한 작업 세션이 **두 번째 task** 를 받는 것 | spec 을 쓰는 순간 `pre-commit` 에 걸린다(브랜치가 base 이후로 spec 을 둘 추가하면 거부). **브랜치를 새로 자르면 안 걸린다** | 세션의 수명은 훅이 볼 수 있는 것이 아니다 |
| 진행 중인 작업 세션과 갓 열린 세션의 구별 | 없다 | 같은 뿌리다 |
| `reap` 을 안 하고 끝난 세션의 사본 | 남는다. 디스크만 먹고, 사람이 지운다 | **의도한 트레이드오프다.** 남의 사본까지 거두려면 판정을 저장소 전역으로 넓혀야 하는데 **그게 병렬 세션을 깨뜨렸다** — 사고로 배웠다(`harness.md` 의 정리 절) |
| 실행자가 원문 대신 요약을 실어 넘기는 것 | 못 막는다 | 아래 '일부러 없는 것' |

## I — 작업 절차서를 누가 쓰는가

**증상.** `developer` 가 *무엇을 어떤 순서로 왜 그렇게* 만들었는지가 어디에도 안 남는다. 산출물은 코드와 테스트뿐이고, `qa-checklist.md` 는 spec 대조표라 구현 경로를 담지 않는다. **결과는 남고 경로는 안 남는다.**

**근거 — 실제로 비어 있는 자리 둘.**

| 어디 | 지금 무슨 일이 생기나 |
|---|---|
| **통합 red 복구** | 머지된 `HEAD` 에서 `developer` 를 새로 스폰하는데 **그 컨텍스트는 앞선 구현들을 모른다** — `harness.md` 의 해당 절이 직접 그렇게 적는다. 읽을 것이 코드밖에 없다 |
| **순차 파이프라인의 dev→dev** | dev2 의 worktree 에 dev1 코드는 들어 있지만 **왜 그렇게 짰는지는 안 들어 있다** |

**세 안을 재봤다**(2026-08-24 논의).

| | 안 1 기획자 모드 | 안 2 새 서브에이전트 | 안 3 `developer` |
|---|:---:|:---:|:---:|
| 사람 승인 경계 안인가 | ✅ | ❌ | ❌ |
| 얼림 문제 | ❌ 멈춤 조건(닫힌 집합)에 구멍 | ❌ 승인 밖 문서가 구속한다 | ✅ 없다 |
| 요구사항 채널 수 | 1 | **2** | 1 |
| 층 1 부담 | 무변경 | 새 자리(`qa` 의 `only` 복제) | **deny 한 줄이 열거로 뒤집힌다** |
| 정확도 | 낮다 — 코드가 아직 없다 | 높다 | **최고** — 구현자가 쓴다 |
| 구조 비용 | 0 | 표 다섯 군데 | 한 곳 |

**안 2 는 탈락이다.** spec 이 유일한 요구사항 채널이라는 전제가 깨진다 — `03232d8` 이 tools 에서 `Agent`·`SendMessage` 를 빼면서까지 지킨 것이 그것이다. 그리고 사람 승인 밖에서 만들어진 문서에 구속력을 주면 승인 모델과 정면으로 어긋나고, 안 주면 자리를 세울 이유가 없다 — **어느 쪽으로 가도 값이 사라진다.** 종료 훅이 객관 검사할 것도 "파일이 있다" 뿐이라 층이 아니라 장식이 된다. 하네스 자신의 서브에이전트 기준(사람 입력 없이 완결 · **병렬성이 실제로 필요** · 오래 살 필요 없음)에서도 둘이 탈락한다.

**안 3 이 유력하다.** 얼림 문제가 셋 중 유일하게 없고(자기가 쓰고 자기가 고치므로 멈춤 조건에 구멍이 안 뚫린다), 채널이 안 늘고, 위 표의 두 구멍을 정확히 메운다. 유일한 실비용인 층 1 은 **셋 중 유일하게 테스트로 봉할 수 있는 종류**다. 대신 순서를 강제할 수단이 없다는 것은 받아들여야 한다 — "계획 먼저, 구현 나중" 을 볼 게이트가 없어 같은 턴 안에서는 사후 합리화와 구분되지 않는다.

**안 1 은 새 문서가 아니다.** 기획자가 파일 단위 계획을 쓰는 것은 아래 **일부러 없는 것** 의 두 번째 항목 그 자체다 — 코드가 없는 시점의 정확도를 믿을 수 없어 보류해뒀다. 안 1 이 노리는 것(구현 전 방향 합의)은 이미 spec 의 `방식`·`주의`·`범위 밖` 이 맡은 자리이므로, 필요하면 **새 문서가 아니라 그 필드를 두껍게 쓰는 것**이 답이다.

**미결 — 착수 전에 이것부터 정한다: 절차서의 독자가 사람인가, 다음 에이전트인가.** 사람이면 안 1 계열이고 새 파일이 아니다. 다음 에이전트면 안 3 이다. **이 답이 없으면 만들지 마라** — 독자가 없는 문서가 어떻게 죽는지는 `harness/index.json` 이 보여줬다.

*어디를 만지나*(안 3 으로 갈 때) — `.claude/hooks/path-ownership.mjs:82` 에서 `developer` 의 deny 를 `<specRoot>/**` 한 줄에서 `spec.md`·`qa-checklist.md` 열거로 좁힌다. **같은 커밋에 회귀 테스트 세 줄이 반드시 붙는다**(spec.md 는 막힌다 · qa-checklist.md 는 막힌다 · 절차서는 열린다) — 열거로 바꾸는 순간 나중에 `harness/` 아래 세 번째 산출물이 생겼을 때 **빠뜨리면 조용히 열리기** 때문이다. 그밖에 `.claude/agents/developer.md`(산출물 목록), `.claude/harness.md`(회수 절), `.claude/planner-mode.md`("절차서는 spec 을 대체하지 않는다" — spec 이 얇아질 유인을 막는다).

> **절차서를 `harness/` 밖에 두는 우회로는 없다.** 층 1 의 어느 규칙에도 안 걸리면 `defer` 인데, `developer` 는 `unattended` 라 거기서 승인 프롬프트가 뜨면 **종료 훅조차 안 돌고 죽는다**(실측된 사망 경로). 명시적 허용이 필수라 층 1 은 반드시 손댄다.

## 순서

**G 의 다섯은 순서가 없다** — 서로 안 물린다. 다만 무게는 다르다:

- **G-1(`spawn` 이 도달을 강제)** 과 **G-2(층 1 fail-closed)** 가 값이 크다. 지금은 하네스가 반쯤 설치된 저장소에서 **막히지 않고 그냥 통과한다**
- **G-3(POSIX 실행권한)** 은 이 기계에서 못 한다 — CI 가 먼저다. **H-1(macOS `spawn`)이 같은 기계를 기다린다**
- **G-5(`.harness/` 이주)** 는 착수 전에 **할지 말지부터** 정해야 한다. 경로가 바뀌는 일이라 나머지가 끝난 뒤가 안전하다

H 는 G 와 경합하지 않는다. **H-1 은 이제 G-3 과 같은 종류다** — 코드가 아니라 **기계**가 없어서 막혀 있다(둘 다 POSIX 에서 한 번 돌리면 끝난다). H-2 는 애초에 고칠 대상이 아니다.

**I 는 G·H 어느 것과도 안 물린다.** 다만 G-5 와 성격이 같아서 **착수 전에 할지 말지부터 정해야 한다** — 그 판단이 나기 전에 손대면 독자 없는 문서가 하나 는다.

이 문서에 **일부러 없는 것** 셋:

- **실행자가 원문 대신 요약을 실어 넘기는 것.** 요약과 원문은 문자열로 구분되지 않고, "사람이 실제로 논의했는가" 는 훅이 판정할 수 있는 종류가 아니다. H-2 에 못 막는다고 적어두는 것이 전부다
- **spec 에 기능별 '건드릴 파일' 을 적는 것.** 병렬 스폰 판단에 근거가 생기지만, 코드가 없는 시점에 파일을 적는 것이 얼마나 정확할지 모른다. 순차가 기본이 된 지금은 급하지 않다 — **병렬이 실제로 필요해질 때 판단한다**
- **작업 세션끼리 파일 소유가 겹치는지 볼 수단.** **구조가 바뀌면서 문제 자체가 사라졌다.** 예전에는 기획자가 서브에이전트라 spec 을 쓰는 자리와 그것을 읽어 `developer` 에게 배분하는 자리가 갈려 있었고, 소유가 겹치는지는 그 배분하는 자리에서만 물을 수 있었다. 지금은 **한 작업 세션이 자기 spec 을 쓰고 그대로 이어서 돌린다** — spec 이 곧 그 세션의 범위이고, 개발은 그 spec 을 근거로만 움직인다. 본체에 목록 파일을 두는 안이 자연스러워 보이지만 그건 `harness/index.json` 의 재래다(쓰기만 하고 아무도 안 읽는 파일)
